# EVOLVE5 上板验收

本包离线验证完成后发布，尚无本版实板结果。板卡仍为RK3568_MES2L100H / PG2L100H-6IFBG484，25MHz；已确认的引脚和电平沿用原基线。

## 下载前核对

运行scripts/verify_package.py检查全部文件。只下载release.json所引用的balanced/speed位流，具体文件名及SHA-256以该清单为准；work目录和失败PDS报告对应的位流不能下载。实际串口号和JTAG连接需重新枚举，旧COM9不是固定值。

| 身份 | balanced | speed |
|---|---|---|
| 固件BUILD | EVOLVE1_BOARD | EVOLVE1_BOARD |
| IMPL_ID | 000325ff | 000328ff |
| FRONT_CFG | f1540086 | f1840886 |
| BTB / RAS | 32 / 0 | 256 / 8 |
| ISSUE_CFG | d1000003 | d1000003 |
| MISA / HW_CFG | 40001100 / 0000003F | 40001100 / 0000003F |

BUILD保留的是冻结编译阶段的固件名称，不代表下载了旧硬件。两配置共享同一GCC15 O2+LTO固件，硬件身份由IMPL_ID和FRONT_CFG区分；下载日志与位流哈希一起保存，UART身份本身不是位流认证。

## 启动和现象

串口115200、8N1，应完整出现RISC-V COREMARK 1.0、身份信息、M_CHECK PASS、DUAL_CHECK PASS、PORT_CHECK PASS及首个CM_READY。

DUAL_CHECK是计时区间外的独立ALU循环，iterations=1024、instret=34818，pairs应非零，cycles小于34818。它证明双退休能力，不能把其IPC当作CoreMark IPC。LED仅作辅助观察。

任何FAIL、无READY、乱码、意外重启均保存完整日志作为诊断，不当作通过。

## 正式两套种子

关闭其他占用串口的程序，下载对应位流后从工程根目录运行：

```powershell
.\scripts\run_board_coremark.ps1 -ListPorts
.\scripts\run_board_coremark.ps1 -Port COMx -Variant speed -Iterations 2048
```

COMx替换为实际端口。脚本不负责下载；它检查发布位流哈希，发送软复位和b 2048，保存uart.txt、session.json，并调用本版验收器生成validation.json。

也可以手动发送b 2048加换行。必须等performance与validation两条CM_RESULT及最后CM_READY；每套应有crc_ok=1、time_ok=1、score_valid=1，实际周期均达到10秒门槛。依据短仿真，整对约43～45秒，再加启动和UART开销；这只是等待预算，正式分数按实板CM_RESULT原始cycles计算。主机默认超时300秒。

每配置建议3轮，每轮软复位后保存一次完整启动至最终READY。另做一次KEY0实体复位并确认重新完整自检。GPIO软件复位和KEY0硬件观察都属于实板验收事项，本包未宣称实板完成。

## 手动校验与记录

```powershell
& 'C:\Users\LZM\AppData\Local\Programs\Python\Python312\python.exe' .\scripts\verify_dual_log.py .\uart.txt --config speed --origin board --iterations 2048
```

balanced则修改config/Variant。每文件包含一次完整启动、一套performance+validation，不能混入多轮或只截成绩。q/w和8次迭代输出是短正确性测试，无法作为正式成绩验收。

保存两份下载位流的文件名、SHA-256、编程日志、串口设置、完整UART、session.json、validation.json、板卡及复位观察。报告全部三轮，不只取最好一次。

CoreMark IPC目前来自RTL独立退休统计；正式实板CoreMark/MHz可由cycles计算。要取得实板IPC，还需对应片上退休/周期计数采集或DebugCore证据，不能把仿真IPC直接写成实板IPC。旧STRESS1/DBG1的实板验收不是EVOLVE5的长压力或抓波证据。
