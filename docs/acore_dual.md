# Acore 顺序双发射设计与上板说明

## 当前交付状态

报告位于 `reports/acore_dual/resources.prr`、`timing.rtr`、`timing_summary.txt`，
`implementation.json` 明确区分这份已完成的 RTL 实现与等待用户构建的最终固件。

## 以 Acore 为基础的改动

`Acore.v` 增加可选第二槽。`ENABLE_DUAL=0` 保留原单发射 PC、ROM、冒险检测路径；
`ENABLE_DUAL=1` 使用双字取指与四操作数前递。A/B 都例化原来的 `decoder` 和 `ALU`；
原 CSR、乘法器及除法器执行逻辑保持不变，分支预测器增加共享同一张表的第二个查询端口。
没有 Cache、寄存器重命名、ROB 或乱序调度，数据总线仍然每拍最多一次访存。

## 配对规则

始终检查相邻的 A、B 两条，A 较老、B 为 PC+4。支持下列组合：

| A 槽 | B 槽 | 条件 |
|---|---|---|
| 普通整数 ALU / LUI / AUIPC | 普通整数 ALU / LUI / AUIPC | 无 RAW/WAW |
| load 或 store | 普通整数 ALU / LUI / AUIPC | B 不依赖 A 的结果 |
| 普通整数 ALU / LUI / AUIPC | load 或 store | B 的地址、store 数据均不依赖 A |
| 普通整数 ALU / LUI / AUIPC | 条件分支、JAL、JALR | B 的源和链接目的寄存器无冲突 |

每组至多一次访存、一次控制流变化。A 为分支/跳转时独占一组，保证控制指令总位于组的末尾。
乘除法、CSR/MRET 和 FENCE 仍独占；两条访存不能共用当前单端口 CPU 数据通路。

RAW 检查只看真实源寄存器；store 的立即数字段不作为目的寄存器，分支也没有目的寄存器。
LUI/AUIPC 没有 GPR 源，x0 不参与写相关。禁止同组 WAW，允许 WAR，因为操作数先读取、结果后写回。
没有 A 同拍计算结果再送 B 的串联 ALU 旁路；`addi x5,x1,1; add x6,x5,x2` 仍拆成两组。
不能配对时只取走 A，B 留在队头，下次再尝试；不跳过 B 找后面的指令。

## 取指端的三个改进

程序存储器是紫光 8192×32 真双口 DRM IP `pango_acore_fetch`，写口均关闭。
两端口读取 PC、PC+4，容量仍为 32 KiB，同步读取一拍；额外输出寄存器关闭。

1. **返回旁路**：八项队列为空时，ROM 刚返回的指令直接送译码，无须先入队再多等一拍；
   队列只剩一条时，也可以和刚返回的一条组成双发射组。停顿时未消费的返回数据才进入队列。
   信用计算同时考虑队列、在途响应和本拍消费，避免覆盖、丢字和重复取指。
2. **双地址预测**：原 BTB 同时查询 PC 与 PC+4。若第一条预测跳转，只保留第一条；
   否则保留两条，再根据第二条的预测选择下一次地址。每条指令携带自己的预测标志和目标。
   两个查询共享表内容，不复制整个 BTB；每拍仍只训练实际执行的那一条分支/跳转。
3. **重定向当拍取指**：发生纠错、中断或 MRET 时，清除旧队列，ROM 地址当拍切到新目标。
   下一拍可通过返回旁路使用目标指令。该请求先按顺序取两个字，再恢复正常预测。
   因此取指指针可能已经是目标+8，不代表目标的两条指令已经执行。

目标允许四字节对齐，不要求八字节对齐。ROM 范围以外返回 NOP，数据访问仍沿用原地址图。

## 共享访存与写回

B 槽现在保留译码器的 MemRead/MemWrite、大小和符号控制。
每组只会有一个槽请求 LSU，地址、store 数据、大小和字节掩码随所属槽选择。
ROM 0x00000000–0x00007fff、RAM 0x00010000–0x0001ffff、MMIO 0x00030000 段保持不变。
数据 RAM 64 KiB、Transparent_Write，CPU 只用 A 口。

读请求还携带结果属于哪个槽的标志，RAM/MMIO 一拍后的返回只送该槽。
这样 B 读取 UART 状态时不会误把设备数据写进 A 的 ALU 目的寄存器。
B 的 load、ALU/LUI 及跳转链接结果分别选择 RAM/设备、运算结果及 B_PC+4（组首 PC+8）。
store 和条件分支的目的寄存器为零，不产生实际 GPR 写入。

## 寄存器堆与冒险

寄存器堆仍为 31×32 bit 架构数据、四读两写；x0 固定为零。
对每个真实源按“紧前组 B、紧前组 A、写回组 B、写回组 A、GPR”选择最近生产者。
阶段优先于槽位，较新的 A 必须覆盖更旧的 B；同组中 B 较年轻。

两个槽的 load 都可能尚未就绪。最近匹配到 load 时，整组停顿，不能退回更旧的同名值。
ID/EX 两槽一起保持，EX/MEM 注入空泡，老组继续排空。
数据源包括 ALU、store、分支、CSR 和乘法操作数，均能看到前组两个槽的结果。
乘除法沿用原 busy/ready 协议且独占，关闭硬件除法后只保留 Zmmul，软件通过 libgcc 做除法。

## 分支、冲刷与中断

B 为控制指令时，在 B 的 PC 上计算目标、比较条件及生成链接值。
组级预测核对选择 B 自身的预测元信息，BTB 训练也使用 B_PC。
若预测错误，A 和 B 本组仍完成，只冲刷更年轻的队列/译码内容。
不跳转的正确后继是组首 PC+8，跳转时为 B 的实际目标。

中断只在有效指令组可以推进时接受。A/B 本组均继续完成，mepc 指向下一条尚未执行的指令。
若存在错误预测，使用实际目标或真实顺序后继，不保存错路径队头。
CSR/MRET 独占，避免同时更新中断状态。没有新增同步异常架构，未映射访问仍使用原来的 bus_err。

## CoreMark 固件与串口

算法源 `third_party/coremark/` 未修改；移植源在 `csrc/coremark_port/`。
默认 **O2、2700 次、2000-byte 工作集、单上下文、25 MHz**，按用户先前实板速度预计约 30.4 秒。
这是固定迭代数的估计，不是精确的 30 秒定时停止，最终时长以硬件周期计数器为准。

UART 使用真实 MMIO 外设，115200 / 8N1 / 无流控。USB-TTL RX 接 FPGA TX（AB21、扩展口第3脚），共地。
板载 CH340 接 RK3568；CoreMark 输出不经过该口。
移植层不再打印编译器版本、编译参数和重复的带元数据总分行；编译信息保存在 firmware manifest 中。
保留时间、迭代数、CRC、验证结论，并增加：

```text
CoreMark        : <每秒迭代数>
CoreMark/MHz    : <每秒迭代数 / 25>
COREMARK DONE
```

分数在 stop_time 之后计算和发送，不计入测量窗口。
归一化公式直接使用 `iterations × 1000000 / ticks`，而不是用已经取整的串口时间。
错误和不足十秒警告不会被过滤。短测试输出的分数仅用于验证计算，不能作为有效成绩。
用户之前报告的 1000 次实板结果为 281873350 周期、11.274934 秒、88.692315 CoreMark，
对应 **3.547692607 CoreMark/MHz**。这是旧输出格式的实板观察，不是最终 2700 次固件的已测成绩。

## 验证与报告

- 四组随机程序逐条比较单/双发射 PC、机器码和写回值，并比较最终 64 KiB RAM。
  包含 B 槽 load 的等待、读后写覆盖、WAR、字节访问、分支和跳转冲刷。
- 双发射中断回归覆盖 20 项，包括 B 槽 load、MMIO store、条件分支、JAL/JALR 边界，检查全部 GPR 现场。
- 原单发射 16 项 CSR/中断回归保留。
- 官方 ROM/RAM、16 种字节写掩码和 397 项乘法检查保留；两组 CoreMark 短跑检查标准 CRC。
- 新精简串口已用单次迭代短跑检查 CRC 和两项分数计算。最终 2700 次留给用户上板验证。
