# INT16残差ADD：把两条分支的特征图相加

日期：2026-10-26。状态：计算单元、DDR读写、CPU任务表和混合卷积/ADD网络已通过行为仿真；尚未综合上板。

## 1. 这个模块做什么

网络分出两条路径，算完后需要把结果融合：两张特征图的高、宽、通道数必须相同，对应位置相加。
CPU只指定两张输入图、输出图和缩放参数的DDR地址，输入读取、加法及输出写回均由硬件执行。

```text
DDR输入A → 乘MA并右移舍入 ─┐
                         ├→ 相加 → INT16饱和 → DDR输出 → 后续卷积
DDR输入B → 乘MB并右移舍入 ─┘
```

为什么不是直接相加整数码：两条分支可能采用不同量化尺度，先换算到共同输出尺度才有意义。
此文记录ADD阶段；随后已实现 [通道Concat](concat_int16.md)，池化、上采样和完整检测网络仍待完成。

## 2. 数值规则

```text
rhu(x,s) = s==0 ? x : arithmetic_shift_right(x + 2^(s-1),s)
y = clamp(rhu(A*MA,SA) + rhu(B*MB,SB), -32767,32767)
```

- 输入、输出是有符号INT16；乘数为0..2^31−1，右移为0..63。
- 两路必须分别舍入后相加；不是先相加再统一缩放。
- 相加之前不能分别饱和到INT16；例如20000×3−10000×3应得30000。
- RHU(+0.5)=1、RHU(-0.5)=0；与参考C `add_point`一致。
- 没有偏置，没有额外ReLU，也不经过卷积的Q13中间域钳位。

`vsrc/add_int16.v`提供输入/输出valid-ready握手，锁存乘积和右移量，输出反压期间保持结果。
一个计算器分时处理DDR字中的8个INT16元素，不扩大原4×2卷积MAC阵列。
乘法器、量化路径实际占用和频率仍需真实IP及PDS验证。

## 3. DDR引擎如何执行

扩展现有 `conv2d_ddr_engine`，与卷积复用 `ddr_chunk_client`、块搬运器和整层DDR所有权。
不新增第二套DDR仲裁，不在原生事务中间抢占，不调用CPU逐元素计算。

1. 读取一次16字节ADD参数。
2. 按16字节读取A、B各一个字。
3. 逐个计算8个元素，组成一个输出字。
4. 写回16字节，继续下一字，直至完整张量完成。

布局仍为H-W-align16(C)，每元素2字节。
无效通道的输入可以非零，写回时仍显式补零；不依赖输出预清零。
输出禁止与A、B或参数表重叠；A和B允许使用同一输入地址，不提供原地输出。
状态、错误、复位和原生FAULT规则沿用现有引擎。ADD的mac_issues为0，cycles仍统计整层执行周期。

## 4. CPU寄存器及任务表

新增 `AI_OPCODE @ 0x30248`，复位为1：1=CONV2D，2=ADD。
该寄存器与其余配置一起忙时冻结，通过稳定邮箱跨域，上板需覆盖相应最大延迟约束。

ADD复用现有寄存器：

| 寄存器 | ADD含义 |
| --- | --- |
| AI_INPUT | 输入A地址 |
| AI_WEIGHT | 输入B地址，此模式下不是卷积权重 |
| AI_OUTPUT | 输出地址 |
| AI_QUANT | 16字节参数表地址 |
| AI_HW | H、W |
| AI_CHANNELS | 低16位和高16位均为C |
| AI_POST | 必须为4 |
| AI_CONV、AI_BIAS、AI_GROUP | 必须为0 |

参数表小端四个u32：MA、SA、MB、SB。
只在16位硬件上提供ADD；8位硬件拒绝该操作。

AIM1版本2继续使用64字节任务：opcode=2，第1字为A地址、第2字为B地址，其他字段按上表填写。
CPU预检查全部描述符再执行；B地址按整张INT16张量检查，参数表仅需16字节。
CPU不能从任意地址推导张量形状，两个输入的形状一致性由打包工具根据已有张量检查。

模型JSON示例：

```json
{
  "name": "residual",
  "op": "add",
  "input": "earlier_layer",
  "input_b": "latest_layer",
  "quant_add": [1, 0, 1, 0]
}
```

本例整数码直接相加；真实模型使用C资产导出的比例。
不能混入卷积权重、偏置、group_split、ReLU等字段。
ADD输出作为普通INT16张量登记，下一层可直接引用该层名称。

## 5. 仿真结果和复现

```bash
make test-ai-add
# 只导出C期望值、打包并编译，不启动仿真：
python3 pc_ai/verify_w8a16_tasks.py --suite add --prepare-only
# 更多CPU/DDR时钟组合，由用户运行等待：
python3 pc_ai/verify_w8a16_tasks.py --suite add --profiles all
```

输出集中在 `pc_ai/outputs/add_tasks/`，数学期望值由原C `add_point`/`conv_layer`计算。
Python只负责打包和测试调度，不独立重写网络数学参考。

- 单元：969个向量，加2次复位重放，共971次输出检查；包含参考资产全部10份ADD参数、补充极值、舍入/饱和、参数锁存、反压及非法参数。
- DDR：15种配置，含不同H/W/C、通道尾部、两输入独立数据、跨2KiB、512MiB顶部地址；每组检查236个128位结果字，含2次重放。
- DDR正常、随机停顿和零读写延迟三种配置通过；22种非法配置/参数拒绝，计算中复位、原生超时FAULT及共同复位恢复通过。
- CPU：三个网络，包括参考model.2的两层3×3卷积与真实残差ADD、补充的卷积→ADD→卷积和分支、两层ADD。
- 同次运行22次模型请求、18次AI提交，检查6717个DDR字；18种错误、后续层预检查、运行中参数错误及不复位重跑均通过。
- CPU只写报告，不搬运分支或代算ADD；检查输入、全部输出/填充、只读资产、哨兵及cycles/issues报告。
- 原生故障停止和8位硬件拒绝16位模型的检查通过。
- 默认CPU任务测试为25MHz/DDR用户时钟约131.25MHz；额外组合是否执行以result.json为准。
- 加入ADD后统一固件3444字节，初始化数据段0；`ai_run_model`自身栈帧240字节，不代表完整调用栈峰值。
- 受影响的旧W8A8任务测试及W8A16纯卷积任务测试通过；未运行CoreMark。

这些是独立残差块和小网络行为仿真，不是整个YOLO推理，不是检测精度验收，也不是PDS/实板性能。
