# 可配置卷积：模型未确定时先实现什么

状态：单层原始整数卷积已实现并通过独立对拍；尚未接入 CPU 控制寄存器、DDR 缓存和量化/激活。不能据此宣称已经运行 YOLO。

## 1. 三种“参数”要分开

| 类别 | 例子 | 何时确定 |
| --- | --- | --- |
| 硬件能力 | 乘法器数量、操作数位宽、缓存容量、支持的算子 | 综合前 |
| 每层配置 | 输入高宽、输入/输出通道、卷积核、步长、padding、数据地址 | CPU 每次提交任务时 |
| 模型数据 | 训练权重、偏置、每层或每通道量化尺度 | 训练/导出后加载到 DDR |

不知道权重的具体数值，并不影响实现乘法器和卷积循环。例如一个乘法器可以计算任意合法位宽的两个操作数，不必提前知道它们是 3 和 -5。
尺寸也可以由计数器和命令寄存器控制，不必为每层重新综合。

这不意味着任意模型都能直接运行：必须满足已支持的算子和整数语义。模型选择和软件参考仍需同步推进，尤其要在实现输出量化之前确认其数值规则。

## 2. 本版的计算定义

`vsrc/conv2d_core.v` 在一个时钟域内执行：

```text
output[y,x,co] = bias[co]
              + sum(input[y*stride+ky-padding, x*stride+kx-padding, ci]
                    * weight[co,ky,kx,ci])
```

超出输入边界的值为零；深度学习中的卷积不翻转权重核。未开启偏置时以零开始累加。

支持：

- 输入高宽、输入/输出通道数：运行时配置，1～65535。
- K=1/3，stride=1/2，四边相同的 padding=0/1。
- 有符号操作数，偏置为有符号 32 位、且已经位于乘加的整数尺度。
- 输出高宽按 `floor((input+2*padding-K)/stride)+1` 计算，使用 17 位，避免 65535 加 padding 后回绕。
- 单个乘法器复用，保留 64 位完整累加结果；输出按 HWC 顺序产生。

64 位原始结果用于先验证数学正确性，**不代表今后的所有特征图都按 64 位存 DDR**。
在操作数不超过 16 位、输入通道不超过 65535、K 不超过 3 的范围内，乘加项数小于 `2^20`，单项绝对值不超过 `2^30`，加上 32 位偏置也不会溢出 64 位累加器。

本模块不执行重定标、舍入、饱和、ReLU、池化、ADD、拼接、深度可分离卷积或分组卷积。
它只处理单个 batch，不承担整个网络的连接关系。

## 3. 位宽与 INT8 的关系

`ACT_WIDTH`、`WEIGHT_WIDTH` 是综合参数，默认均为 8。**当前版不能在运行时切换这两个位宽**；运行时可变的是层的尺寸和卷积配置。

| 回归配置 | 权重 | 输入特征值 |
| --- | --- | --- |
| W8A8 | INT8 | INT8 |
| W8A16 | INT8 | INT16 |
| W9A16 | 有符号 9 位 | INT16 |

W9A16 用于检查更宽权重的数学通路，不等于已导入 CNN_FPGA 模型。

INT8 量化是常用部署方案，但不是把浮点数直接强制转换成 `int8_t`：

```text
真实值 ≈ scale × (整数值 - zero_point)
```

卷积后还要按输入、权重、输出的尺度关系重新缩放，并定义逐通道尺度、舍入、饱和、偏置位置及激活函数。
本版把输入视为已经归零点的整数，即硬件补零对应真实零。尚未处理非零 zero_point 的修正，不能把任意非对称量化模型直接送进来。
8 位通路也不能直接表示 0～255 的全部原始 RGB 值；需要模型约定的预处理/量化。A16 可以容纳这些整数，但同样必须对齐模型尺度。

第一个参考工程当前的 `training/qat.py` 明确采用权重 INT8、激活 INT16；其 `rtl/mac_array.v` 也为 INT16×INT8，`rtl/requant_pipe.v` 接收 48 位累加值。
其导出 C 模型还存在 Q13 中间域、缩放后加偏置和再次缩放，不能把它的 bias_q13 当成本模块的原始累加偏置直接相加。

因此，验证 W8A16 仅说明基本乘加数值范围能够覆盖该格式，不说明已经复现其模型量化。

## 4. 模块接口与职责

### 命令

`cmd_valid && cmd_ready` 时锁存全部 `cfg_*`。执行期间改变配置输入、再次启动或清状态均忽略。
`done/error` 保持到下次接受命令，或空闲时 `clear_status=1`。

| 错误码 | 含义 |
| --- | --- |
| 0 | 无错误 |
| 1 | 高宽或通道数为零 |
| 2 | 不支持的 kernel、stride 或 padding |
| 3 | 输入加 padding 后小于卷积核；或内部非法状态 |

非法配置不产生操作数请求。形状合法并不保证张量能装进实际 DDR，容量、地址和生命周期仍由导出工具及上层检查。

### 操作数请求/响应

- `req_valid/req_ready`：一次请求握手。
- `req_bias=1`：按 `req_out_ch` 取偏置；其它坐标忽略。
- `req_bias=0`：按 `req_in_y/x/ch` 取输入，按 `req_out_ch/ky/kx/in_ch` 取权重。
- `rsp_valid/rsp_ready`：一次响应，返回输入/权重或偏置。
- 最多一条已接收、未响应的请求。响应必须保持到握手，不能只打一拍脉冲。
- 请求等待时保持有效和载荷；padding 的越界位置直接跳过，不向存储发请求。

**这些请求由未来的加速器缓存适配器服务，不应让 CPU 逐次提供乘法操作数。**
当前 testbench 用存储数组模拟这个适配器；没有访问 DDR，也不涉及 CPU/DDR 跨域。

### 输出

`out_valid/out_ready` 传递一个输出点：64 位 `out_sum`、`out_y/x/ch` 及 `out_last`。
反压时保持结果，只有最后一项被接收后才置 DONE。
命令配置简单整数补零，输出尺寸可与实际模型导出布局不同，需要导出工具明确转换。

本模块没有存储等待看门狗；操作数提供者必须最终响应，未来上层也需提供超时和共同复位机制。
复位会中止计算，必须同时清除适配器的在途请求/响应。

## 5. DDR 中放哪些东西

| 内容 | 位置 | 生命周期 |
| --- | --- | --- |
| CPU 驱动、调度、后处理程序 | CPU ROM | 固件 |
| CPU 栈、状态、少量描述符 | CPU RAM | 按程序使用 |
| 权重、偏置、量化常量、任务表 | DDR | 模型加载后复用多帧 |
| 输入图像/预处理后的输入张量 | DDR | 每帧更新 |
| 中间特征图、检测输出 | DDR | 按网络连接关系保存/复用 |
| 当前计算块、权重块、部分和 | 加速器片上缓存 | 随分块计算更新 |

DDR 中的输入是像素/量化张量，不能把 JPEG/PNG 压缩文件直接交给卷积核心。
分支连接需要的特征图必须保留到最后一个消费者完成，不能简单地每层覆盖同一个输出区。

后续单层闭环的数据流：

```text
CPU 取任务并配置地址、尺寸
  → 加速器从 DDR 分块读取输入和权重
  → 片上缓存向 conv2d_core 提供操作数
  → 原始累加 → 按模型定义量化/激活
  → 输出块写回 DDR
  → 完成后 CPU 提交下一层
```

CPU 不负责每一次乘法，也不通过现有 MMIO 窗口搬运推理过程中的每一个操作数。
首版装载阶段和计算阶段交替使用 DDR，之后再考虑 DMA 仲裁、双缓冲和预取。
