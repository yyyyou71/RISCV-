# Multiply-Adder 行为模型与后续单层闭环

日期：2026-10-25。

模型：`vsrc/multiply_adder.v`。依据工作目录的《简单乘法器.pdf》UG041003 第 2.3 节（第 14～18 页）和第 2.6.1 节（第 29～30 页）。
已读取表格并查看接口/寄存器结构图；目前未取得该配置的厂商生成 RTL，尚未与厂商仿真模型逐拍对拍。

## 1. 手册中的三种运算

| IP | 数学运算 | 是否在内部保存跨拍部分和 |
| --- | --- | --- |
| Simple Multiplier | `p = a*b` | 否 |
| Multiply-Adder | `p = a0*b0 ± a1*b1` | 否 |
| Multiply-Accumulator | `p = p ± a*b` | 是 |

本次实现的是 **Multiply-Adder**。它能同时计算两项乘积及其和，但不会把上一拍结果自动加进下一拍。
卷积可将它接到独立部分和累加器：`acc ← acc + pair_sum`。部分和也可以按输出点保存到片上 RAM。
不能把它直接当作带反馈的 MAC IP。

## 2. 支持的配置与边界

本行为模型支持：

- A0/A1 共享 A 的位宽和符号类型，B0/B1 共享 B 的位宽和符号类型。
- A 有符号 2～73 位、无符号 2～72 位；B 有符号 2～66 位、无符号 2～65 位。
- 静态求和或静态求差；`STATIC_SUBTRACT=0/1`，每次运算的两项乘积使用同一静态符号。
- 0～5 级流水线，关闭 Optimal Timing。
- 高有效同步或异步复位，复位优先于 ce；所有流水级共同使能。

**不支持动态改变 addsub 的模式。**手册列出了动态控制的取值，但没有清楚定义该控制与不同流水级数据逐拍对齐的时刻。
本阶段使用静态求和，避免把未经核实的动态控制延迟当作真实 IP 行为。
`addsub` 输入为与手册接口一致而保留，在静态模式下忽略；推荐连接常量零。

输出位宽按第 18 页脚注 12：`P_WIDTH = A_WIDTH+B_WIDTH+1`。
第 15 页接口图示例的 `p[18:0]` 与其 A=11/B=8 和上述规则存在不一致；模型按明确的位宽规则生成 20 位结果，不照抄该图的结果宽度。
上板时应核对 IPC 实际生成的端口和报告。

所有端口传递原始位向量；输入的数学符号由 A_SIGNED/B_SIGNED 决定。
有符号结果使用二进制补码，调用者应显式用 `$signed(p)` 解释。
无符号减法出现负值时，结果按 P_WIDTH 位回绕；模型不做饱和。

## 3. 默认配置及接口

| 模型参数 | 默认值 | 对应 IPC 配置 |
| --- | --- | --- |
| A_WIDTH / A_SIGNED | 8 / 1 | Port A: Width=8, Signed |
| B_WIDTH / B_SIGNED | 8 / 1 | Port B: Width=8, Signed |
| PIPE_STAGES | 3 | Pipeline Stages=3 |
| ASYNC_RESET | 0 | 不勾选 Async Reset |
| STATIC_SUBTRACT | 0 | 不勾选 Dynamic Addsub，不勾选 Subtract |
| — | — | 不勾选 Optimal Timing |

默认输出为有符号 17 位结果。A=16/B=8 时输出是 25 位，A=16/B=9 时是 26 位。
这些位宽选择属于综合配置，不是运行时改变层参数的接口。

| 端口 | 方向 | 含义 |
| --- | --- | --- |
| a0、a1 | 输入 | 两个 A 操作数 |
| b0、b1 | 输入 | 两个 B 操作数 |
| clk | 输入 | 用户时钟 |
| rst | 输入 | 高有效复位 |
| ce | 输入 | 高有效，全流水线共同推进/暂停 |
| addsub | 输入 | 静态配置下忽略，连接零即可 |
| p | 输出 | 两项乘积之和/差，无 valid 信号 |

固定默认配置的调用方式（不给实例传递行为模型参数，便于换成固定配置的生成 IP）：

```verilog
multiply_adder u_pair (
    .a0(act0), .a1(act1), .b0(weight0), .b1(weight1),
    .clk(clk), .rst(rst), .ce(advance), .addsub(1'b0),
    .p(pair_sum)
);
```

这只是调用示例；本次没有修改 `conv2d_core`，也没有把两路运算接入已有的串行控制器。

## 4. 周期规则与 valid

| PIPE_STAGES | 手册开启的寄存器 | 端口行为 |
| --- | --- | --- |
| 0 | 无 | 组合输出；rst、ce 不影响结果 |
| 1 | XYREG | 第 1 个使能上升沿后得到当前输入结果 |
| 2 | XYREG、PREG | 第 2 个使能上升沿后得到结果 |
| 3 | XYREG、MREG、PREG | 第 3 个使能上升沿后得到结果 |
| 4 | 加 OUTREG | 第 4 个使能上升沿后得到结果 |
| 5 | 再加 INREG | 第 5 个使能上升沿后得到结果 |

“第 1 个”指首次采样本组输入的 `ce=1` 上升沿。
模型用结果延迟队列实现静态运算下的端口等效行为，不逐个复刻 APM 物理寄存器或级联结构。

- ce=0 时全部在途结果和输出保持；暂停周期不计入流水推进。
- 同步复位在上升沿生效；异步复位拉高后立即生效；有寄存器时复位清空全部流水级。
- 0 级没有寄存器，不保证时钟间保持，也没有可复位的流水状态。
- 有寄存器的模式需先复位；不假定上电寄存器内容已知。
- 流水填满后，每个使能时钟可以输出一个 pair_sum，对应两项乘积。实际频率和 APM 数量仍取决于真实 IP 与 PDS 实现。

原 IP 没有输入/输出 valid 或 ready。后续 PE 需要自己维护同延迟的 valid，以及 first/last、输出点标签等元数据。
它们必须随同一个 ce 推进和暂停。`in_valid=0` 的空泡与 `ce=0` 的流水暂停是不同情况：仍有结果在途时，要允许时钟推进以排空流水。

## 5. 替换为真实紫光 IP

1. 在 IPC 为目标器件生成名为 `multiply_adder` 的实例，配置与所选行为模型一致；首版推荐上述默认配置。
2. 比较生成顶层的端口名、位宽、静态操作和复位模式，并核对生成报告的延迟。
3. 在 PDS 源文件列表移除本行为模型，加入生成 IP 的顶层和所需依赖；不要把两个同名模块一起编译。
4. 消费模块若按固定配置、无模型参数覆盖的方式例化，计算控制逻辑可保持不变。
5. 将生成 IP/官方仿真库接入本回归环境再对拍，确认配置兼容后上板。

手册给的是各功能的统一接口表，实际生成器可能按静态选项省略控制端口；若发生此情况，在 IP 边界加一层固定接口薄封装即可。
因此，目前可以保证行为模型的明确契约，尚不能声称对未生成的任意版本 IP 都已验证直接替换。
Optimal Timing 若开启会改变延迟，不能只修改文件列表却沿用旧 valid 延迟。

本模型采用普通 RTL 算术，不保证映射到 APM。资源、时序和板级性能须使用真实 IP 检查。

## 7. 下一步：围绕单层 DDR 闭环实现小规模并行

“分块缓存＋连续供数＋多 MAC 并行”是实现方式，“单层 DDR 计算闭环”是下一阶段的验收目标。
把两者合并推进：

```text
DDR 输入与权重
  → 小块片上缓存
  → 连续读取两个输入值，广播给多个输出通道
  → 各输出通道的 Multiply-Adder 同时计算两项乘积之和
  → 独立部分和累加器/缓存
  → 写回 DDR
  → 与 Python 整数参考逐项比较
```

建议初始规模为 4 个输出通道并行、每通道每次归约 2 项，即 4 个 Multiply-Adder 实例，理论每个有效计算拍共 8 项乘积。
这是待实现的起点，不是已完成的阵列，也不等于 8 个 APM；实际资源映射要看 IPC 报告。

实施顺序：

1. 写可连续供数的小块输入/权重缓存与 4×2 计算通路，先独立对拍。第一轮用单缓冲，不叠加双缓冲和脉动调度。
2. 紧接着连接现有 `ddr_block_transfer`，完成指定地址的输入/权重读入、计算、结果写回；先保持低并行度，不等待大阵列完成。
3. 检查跨输入通道块的部分和保留、奇数通道补零、首末拍与流水排空，以及 16 字节对齐/尾部处理。
4. 接 CPU 任务配置和状态握手；首版让 CPU 窗口与引擎分阶段独占 DDR，不先做复杂并发仲裁。
5. 同步确认可复现模型的量化/激活语义；原始 64 位结果也可用于第一轮 DDR 调试闭环，但不能将其视作已完成模型推理。
6. 记录搬运、有效计算和等待周期，再决定是否扩大并行度、加双缓冲或研究脉动阵列。

缓存要把同一组输入广播到不同输出通道，并复用已读入的数据。不能为每一次乘法重新发起 DDR 小请求。
后续控制器和供数接口需要重新组织；当前 `conv2d_core` 保留为串行正确性基线，不会因换入这个 IP 就自动变成并行引擎。
