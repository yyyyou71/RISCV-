# DDR 任务表与通用 CPU 调度

日期：2026-10-26。状态：第五步已完成行为仿真验收；模型选择按用户要求暂缓。

## 1. 本阶段完成的工作

```text
PC 整数网络描述
  → pack_ai_model.py：布局、补齐、打包
  → DDR：模型头、任务表、输入、权重、偏置、量化表、各层输出
  → CPU：一次读取一条任务 → 配置 MMIO → 启动 → 等待/检查 → 下一条
  → DDR 中的最终输出与运行报告
```

生产 RTL 本阶段没有变化。CPU 的固件不包含测试权重、测试输出或网络专用计算。
`ai_runtime.c` 提供 DDR 窗口驱动和 `ai_run_model(header_addr, &result)`，`ai_task_runner.c` 是预装载仿真的请求列表入口。
SPI 的传输与启动协商尚未接入。测试平台预装载 DDR，正式固件应在外部装载完成后调用运行接口，不能据此认为全套实板装载流程已验证。

同一份固件、同一套 RTL，在一次运行中执行不同网络和恢复测试，中途没有重新编译、复位或修改位宽。
这满足当前支持算子集合内的任务表通用性，不代表任意模型都能导入。
当前只有 CONV2D 操作，支持已有 K=1/3、stride=1/2、padding=0/1、偏置、逐通道重定标、可选 ReLU 和原始 INT64 输出。
量化规则沿用 [INT8 ABI](quantization_int8.md)。

## 2. DDR 布局与数据生命周期

所有地址是 DDR 起点的字节偏移，使用小端。
前 64 KiB 作为运行管理区，模型包从 `0x10000` 起，整个范围不能超过 `0x20000000`。

每个模型包分为两部分：

- `[arena_begin, readonly_end)`：模型头、任务表、初始输入、权重、偏置、量化记录。
- `[readonly_end, arena_end)`：中间图、最终输出和边界哨兵。

CPU 对所有任务做一次预检查，然后再次逐条读取、执行。输出只能写工作区，所有权重/偏置/量化表只能位于只读区，防止输出破坏后续任务的资产。
范围与尺寸乘积使用 64 位计算，拒绝回绕、越界和当前任务的输入/输出重叠。

第一版离线给每个输出张量分配独立空间，并保留到本次推理结束，没有实现生命周期复用、动态分配或原地运算。
因此任务可以按拓扑顺序引用较早层的 INT8 输出；跨层连接不要求把整张图留在片上。
这种引用不等于已实现 ADD/Concat，二者仍需要对应算子。
层间形状、类型与引用关系由打包工具检查；CPU 不在运行时构建完整计算图。

## 3. AIM1 模型头：64 字节

每个字段均为 uint32，以下编号为字索引：

| 字 | 字段 | 内容 |
| --- | --- | --- |
| 0 | magic | `0x314d4941`，字节为 AIM1 |
| 1 | version | 1 |
| 2、3 | header_bytes、task_bytes | 均为 64 |
| 4、5 | task_count、tasks_addr | 任务数量、DDR 任务表地址 |
| 6、7 | arena_begin、arena_end | 整个模型包范围，结束地址不包含在内 |
| 8、9 | input_addr、input_bytes | 初始输入的物理位置与长度 |
| 10、11 | output_addr、output_bytes | 最后一个任务输出的物理位置与长度 |
| 12 | readonly_end | 只读区结束、工作区开始 |
| 13～15 | flags、reserved0、reserved1 | 均为 0 |

头、表和张量地址均按 16 字节对齐；任务数量必须非零。
任务表不得与模型头重叠。输入必须在只读区，最终输出必须在工作区。
地址是打包时确定的绝对 DDR 偏移，移动模型包到不同基地址需重新打包。

## 4. 每条任务：64 字节

| 字 | 字段 | 内容 |
| --- | --- | --- |
| 0 | opcode | 1=CONV2D，其他值拒绝 |
| 1～5 | input、weight、bias、output、quant 地址 | 与现有 AI MMIO 地址语义相同 |
| 6 | hw | 低 16 位 H，高 16 位 W |
| 7 | channels | 低 16 位 Cin，高 16 位 Cout |
| 8 | conv | K[1:0]、stride[3:2]、padding[5:4]、bias_enable[6] |
| 9 | post | bit0=INT8，bit1=ReLU，其他为零 |
| 10、11 | out_h、out_w | 预期输出高宽；预检查公式，完成后核对硬件返回值 |
| 12～15 | reserved | 必须为零 |

原始 INT64 模式可用于最终输出或保留数学结果；不能直接作为后续 INT8 卷积的输入。
CPU 只读取头和任务记录，不读取图像、权重或中间图来完成运算。

## 5. AIR1 运行请求与报告

预装载入口从 DDR `0x1000` 读 32 字节请求：

| 字 | 内容 |
| --- | --- |
| 0、1 | magic=`0x31524941`（AIR1）、version=1 |
| 2 | 模型运行次数，1..64；允许重复指定同一个模型包 |
| 3 | 模型列表地址，默认 `0x2000` |
| 4 | 运行报告地址，默认 `0x4000` |
| 5～7 | 保留零 |

列表每项 16 字节，第一个字为模型头地址，其余三个字为零。
列表和报告必须在管理区内、按 16 字节对齐、互不重叠且不覆盖请求。
默认布局最多容纳 64 项；管理区写入由外部装载完成，CPU 只写每次执行的报告。

每份报告 32 字节，8 个 uint32：

```text
code, failed_task, hardware_code, completed, cycles, issues, out_h, out_w
```

`failed_task=0xffffffff` 表示没有失败任务索引；`completed` 是成功完成的任务数。
`cycles/issues` 累加本模型实际提交过的 AI 任务计数，包括报错任务已有的统计，32 位回绕；不包含 CPU 取表和报告写回开销。
`out_h/out_w` 对应最后成功完成的任务，尚无成功任务时为零。

| code | 含义 |
| --- | --- |
| 0 | 成功 |
| 1 | 头或 ABI 格式错误 |
| 2 | 地址、长度、范围或覆盖关系错误 |
| 3 | 不支持的 opcode |
| 4 | 任务配置、保留位或预期形状非法 |
| 5 | DDR 访问失败或致命 DDR 故障 |
| 6 | AI 引擎返回错误，详见 hardware_code |
| 7 | CPU 轮询超时 |
| 8 | 硬件完成后返回的形状不符 |

完整任务表的格式检查在提交第一层前完成，因此后面任务的描述符有错也不会先执行前面层。
量化表由硬件在执行中验证，后面层报错时，前面层输出会保留；不回滚。
可恢复错误写报告后继续下一份模型。原生 DDR FAULT 时无法再通过同一 DDR 写报告，入口返回非 1 并停止，保留故障状态，不能自行清状态重试。
`ai_run_model` 的结果仍在 CPU RAM，可由正式固件经通信模块上报。
DDR 窗口访问和初始化等待设有 CPU 轮询上限。整层计算的耗时随模型变化，等待 AI 完成不套用块搬运的短上限；DDR 原生故障仍由硬件看门狗返回，仿真另有全局超时。实板整层看门狗需结合选定模型的耗时配置。

仿真入口返回 1 仅表示请求列表处理完毕，不表示每份模型都成功；每份模型以报告 `code=0` 判断。
请求格式错误返回 `0x101/0x102`；入口读写访问失败使用 `0x100+code` / `0x200+code`。

## 6. PC 打包工具与可复现入口

从仓库根目录执行：

```bash
python3 scripts/pack_ai_model.py examples/ai_tasks/two_layer.json \
  --base 0x10000 --output build/ai_example/model.bin \
  --request build/ai_example/request.bin --reference
```

- `model.bin` 从 DDR `0x10000` 装载；`model.json` 提供物理布局与输出地址。
- `request.bin` 是 64 KiB 管理区镜像，从 DDR 0 装载，只含本模型的一次运行请求。
- `--reference` 额外生成各层黄金输出二进制；这些文件用于调试比较，不是需要装载的推理输入。

JSON 的输入按 HWC，权重按 O-KY-KX-I，都是已量化的逻辑数据，不需要手动补齐。
输入可提供 `data` 或 `data_file`（INT8），权重可提供 `weights` 或 `weights_file`（INT8），偏置可提供 `biases` 或 `biases_file`（小端 INT32）。每组必须且只能提供一种；相对路径相对于 JSON。
每层用 `input` 引用 `input` 或之前层的名称，用 `quant` 指定逐通道 `[multiplier,shift]`，用 `relu` 选择激活。
关闭偏置时指定 `bias_enable=false`；原始输出指定 `output_int8=false` 且关闭 ReLU。

工具统一生成补齐后的物理布局，工作区带哨兵，默认初始化为零；打包失败时不会静默将不支持的算子降级为卷积。
Python 接口 `pack_run_request([模型头地址...])` 可生成多模型或重复运行的管理区镜像。
本工具没有训练、BN 折叠、浮点量化校准、ONNX 解析或检测头后处理功能，输入必须已符合当前整数 ABI。

## 7. 仿真验收

```bash
make test-ai-tasks
```

仅编译一次 RV32I 固件和一次 CPU/AI/DDR RTL，所有模型与错误用例均从 DDR 数据给出。
同一请求列表包含 21 次模型执行请求：三种有效网络、17 种非法头/描述符/量化记录，以及最后一次不复位重跑原网络。
有效网络覆盖两层、三层、跨 16 通道、不同 stride、INT64 最终输出，以及按地址复用较早层输出的分支；共实际提交 13 次 AI 任务。
17 个错误用例中只有 2 个量化错误进入 AI，其余在 CPU 头/任务预检查阶段拒绝。

25 MHz CPU、50 MHz CPU/DDR 随机停顿、25 MHz CPU/DDR 零读写延迟三组通过。
每组比较 4626 个 128 位 DDR 字，包括所有层输出、只读区、任务表、哨兵和报告；不是只检查程序退出值。
测试台还检查 CPU 只能写报告区，且报告 cycles/issues 等于实际硬件任务统计之和。
第一份网络的一条任务记录跨过 DDR 2 KiB 列边界，覆盖窗口读表的跨列拆分。

另外运行 7 种请求/列表格式错误，确认零 AI 提交、零报告写入、DDR 内容不变；原生读超时注入确认故障后停止，未假装输出报告或运行后续网络。
打包工具检查不支持算子、错误引用、错误位宽、缺失量化参数、INT64→INT8 错接、非法基地址/请求列表，以及命令行输出与直接打包结果一致。

固件指令段 2792 字节、初始化数据段 0 字节；不分配随层数增长的 CPU 数组。
GCC 栈报告中 `ai_run_model` 自身栈帧为 240 字节；完整调用栈还包括入口、DDR 驱动和编译器辅助函数，不将单函数栈帧冒充整体峰值。
产物保存在 `build/ai_tasks/`：固件 ELF/map/镜像、网络包、布局清单、用例表、黄金内存及各组日志。

本阶段按用户要求只验证新调度、打包和相关 CPU/DDR 接口，不重复运行 CoreMark。
第五步达到的是行为仿真验收，真实 IP、PDS 资源/时序、物理 CDC 约束和板级稳定性仍待验证。
