# 4×2 并行卷积与 CPU→DDR 单层闭环

日期：2026-10-25；2026-10-26 更新量化模式。状态：已完成 RTL、行为 DDR 与 RV32I CPU 联合仿真；尚未完成厂商 IP 对拍、PDS 综合/时序和实板验证。

## 1. 本次真正接入的硬件

```text
CPU（默认 25 MHz，自己的 ROM/RAM）
  → MMIO 配置、请求/完成跨域邮箱
  → DDR core_clk 域的 conv2d_ddr_engine
       ├─ DDR 16/32 字节搬运客户机
       ├─ 输入缓存、四个权重银行
       ├─ 4 个 multiply_adder，每个计算两项乘积之和
       ├─ 四路 64 位累加器
       └─ 四个输出位置的部分和存储
  → 共用 ddr_block_transfer
  → DDR 原生端口
```

新引擎**实际例化**了 4 个 Multiply-Adder，位置为 `conv_mac_tile.g_lane[0..3].u_ip`。
默认配置为有符号 8×8、静态求和、3 级流水线、同步高有效复位；没有给 IP 实例传递行为模型参数，便于后续替换成同配置厂商实例。
`conv2d_core.v` 保留为串行数学基线，不承担这条并行路径。

新增文件：

| 文件 | 职责 |
| --- | --- |
| `vsrc/conv_mac_tile.v` | 缓存、连续供数、4×2 IP 和流水有效信号、部分和累加 |
| `vsrc/ddr_chunk_client.v` | 把一次 16/32 字节请求转换为块搬运器命令和数据握手 |
| `vsrc/conv2d_ddr_engine.v` | 分块、地址计算、DDR 读写和整层遍历 |
| `csrc/software/conv2d_ddr_test.c` | CPU 装载、提交两种独立层任务、读回校验的完整样例 |

CPU 外设入口在现有 `ddr_cpu_window.v`，由 `peripheral_bus.v`、`soc.v` 的 `ENABLE_AI` 参数启用。

## 2. 支持的计算与不包含的功能

- W8A8，输入和权重均为有符号 8 位；偏置为有符号 32 位。
- 非分组卷积，K=1/3、stride=1/2、四边相同的 padding=0/1；单 batch、dilation=1。
- 高宽和输入/输出通道运行时配置，1～65535；完整张量范围必须落在默认 512 MiB DDR 内。
- 输入越界补零，超出实际输入通道的物理填充字节由硬件屏蔽。
- 原始输出为有符号 64 位的 `sum(input*weight)+bias`，不截断部分和。
- 可选逐输出通道重定标、饱和为 INT8，以及 ReLU/激活旁路；其数值 ABI、参数表和层间输出布局详见 [INT8 量化说明](quantization_int8.md)。
- 偏置必须预先换算到原始乘加尺度。

**尚无 SiLU、池化、ADD、拼接或检测后处理，尚未运行完整 YOLO。**
输入视为已经归零点的整数；没有实现任意非零 zero_point 修正。
原始输出格式不能直接作为下一层 W8A8 输入；新增 INT8 模式可直接连接，但相邻层尺度仍需与模型导出一致。
W8A16/W9A16 的串行参考验证不代表这条 W8A8 并行路径已支持那些格式。

## 3. 缓存、连续供数及复用

每个输入通道块固定 16 个通道，每个输出通道组固定 4 个通道。
每个空间小块最多包含同一输出行中相邻的 4 个输出位置。

执行次序：

1. 取当前输出通道组的偏置，初始化四个输出位置的部分和。
2. 取当前 16 输入通道块、当前 4 输出通道的全部权重 tap，装入四个缓存银行。
3. 对一个输出位置，取对应 1×1 或 3×3 输入 patch；padding 部分直接填零。
4. 同步读取输入与权重缓存，每个使能时钟取两个输入值并广播到 4 个 IP，各 IP 取得本输出通道的两项权重。
5. 将 4 个 pair_sum 与同延迟有效标记配平，更新四路 64 位部分和；停止发数后继续排空流水。
6. 重用权重缓存计算另外最多三个输出位置。每个位置的部分和分别保留。
7. 还有输入通道块时，再装入下一块权重/输入，继续原来的部分和；不重复加偏置。
8. 全部输入通道块结束，写回四个输出位置；继续横向小块、输出行和输出通道组。

有效计算拍的容量是 **4 个输出通道 × 2 项乘积 = 8 项乘积**，不等于已测得整层 8 倍加速。
尾部通道、padding 和不足四个输出通道的情况会计算一些零值，不能把所有物理乘法都算成有效模型运算。

本版是输入广播、部分和驻留的并行通路，没有使用脉动阵列。
缓存写入和同步读取分阶段进行；RAM 本体不整体复位，另用有效标记防止未装载启动。
缓存、部分和及客户机的逻辑数据容量约 1.4 KiB，另有原 CPU 邮箱；实际 RAM/LUT/寄存器占用由 PDS 决定，不能按逻辑字节数直接推断 BRAM 数量。

当前采用单缓冲，DDR 搬运和计算尚未重叠。相邻输出位置之间的重叠输入 patch 尚未用行缓存复用；每次 DDR 请求也还只有 16/32 字节。
后续应根据等待周期决定合并突发、行缓存和双缓冲的优先级。

## 4. DDR 数据布局：必须按物理格式装载

所有基地址为从 DDR 起点计算的字节偏移，按 16 字节对齐。
定义：

```text
CIp = align_up(Cin, 16)
COp = align_up(Cout, 4)
Hout/Wout = floor((input + 2*padding - K)/stride) + 1
```

| 张量 | 物理格式 | 字节地址公式 | 分配长度 |
| --- | --- | --- | --- |
| 输入 | H-W-CIp，INT8 | `in_base + ((y*W+x)*CIp+ci)` | `H*W*CIp` |
| 权重 | COp-KY-KX-CIp，INT8 | `w_base + (((co*K+ky)*K+kx)*CIp+ci)` | `COp*K*K*CIp` |
| 偏置 | COp，INT32 小端 | `b_base + co*4` | `COp*4` |
| 原始输出 | Hout-Wout-COp，INT64 小端 | `out_base + ((y*Wout+x)*COp+co)*8` | `Hout*Wout*COp*8` |
| INT8 输出 | Hout-Wout-align16(Cout) | `out_base + (y*Wout+x)*align16(Cout)+co` | `Hout*Wout*align16(Cout)` |

超出实际 Cin 的输入填充可为任意值，硬件会置零；未使用输出通道写零。
权重填充仍应分配足够的物理地址空间；无效输出通道不会发起对应权重读取，而是把该银行填零。
关闭偏置时不会访问 b_base，也不要求它对齐或在有效范围内。
输入必须是预处理/量化后的像素张量，不能直接装入 JPEG/PNG 压缩数据。

读区域之间允许重叠；输出禁止与输入、权重或启用的偏置区域重叠。范围检查使用 64 位大小计算，避免尺寸乘法回绕。
原始模式输出不是饱和值；CPU 通过现有窗口读回一个 INT64 时，先读低 32 位，再读高 32 位。
INT8 模式使用饱和输出，并通过分组读改写组成对齐的 16 字节拍；输出区完成前属于部分结果。

## 5. CPU 寄存器

SoC 使用 `ENABLE_DDR=1, ENABLE_AI=1`。ENABLE_AI 默认 0，保留原有仅 UART/DDR 窗口配置。
CPU 与 DDR 用户时钟保持独立，由原来的双级同步请求/完成邮箱跨域。

| 地址 | 名称 | 定义 |
| --- | --- | --- |
| `0x30200` | AI_CTRL | bit0 START；bit2 CLEAR；其它位忽略 |
| `0x30204` | AI_STATUS | 与 DDR STATUS 共用同一个任务状态 |
| `0x30208` | INPUT | 输入字节基地址 |
| `0x3020c` | WEIGHT | 权重字节基地址 |
| `0x30210` | BIAS | 偏置字节基地址 |
| `0x30214` | OUTPUT | 原始输出字节基地址 |
| `0x30218` | HW | `[15:0]=H, [31:16]=W` |
| `0x3021c` | CHANNELS | `[15:0]=Cin, [31:16]=Cout` |
| `0x30220` | CONV | `[1:0]=K, [3:2]=stride, [5:4]=padding, [6]=bias_enable` |
| `0x30224` | ERROR | 最近任务错误码 |
| `0x30228` | CYCLES | 最近 AI 任务的 DDR 用户时钟周期数 |
| `0x3022c` | ISSUES | 最近 AI 任务的 4×2 供数拍数 |
| `0x30230` | OUT_H | 最近 AI 任务输出高 |
| `0x30234` | OUT_W | 最近 AI 任务输出宽 |
| `0x30238` | POST | bit0=INT8 输出；bit1=ReLU；其余为 0；复位为 0 |
| `0x3023c` | QUANT | 逐输出通道参数表 DDR 字节地址，16 字节对齐 |

STATUS：bit0 BUSY、bit1 DONE、bit2 ERROR、bit3 FAULT、bit4 READY、bit5 INIT_DONE。
AI 和 CPU DDR 窗口共享单槽命令队列及状态，**没有两个可同时执行的独立任务队列**。
先轮询 READY，写完配置，START 后等待 BUSY 清零并检查 DONE/ERROR。忙时配置、窗口写、重复 START 和 CLEAR 均忽略。
CPU 可继续执行自己的 ROM/RAM 程序或访问 UART，但不能同时用窗口抢占 DDR。

原 DDR 窗口仍在 `0x31000/0x31100`，用于装载和读回。
CPU 窗口和 AI 的所有权只在任务间切换，底层块搬运器始终只有一个；不在突发中间抢占。
完成最后一次 DDR 写后才跨域发布 AI DONE。故障锁定时，两种任务均需共同复位窗口、引擎和 DDR IP 才能恢复。

计数器和形状通过稳定响应邮箱一起返回。AI START 清零这些 CPU 可见统计，AI 执行期间读零，完成后保持到下一次 AI START；独立的 CPU 窗口任务不改写这些 AI 统计。
CYCLES 从引擎接受任务后计到完成，包括缓存装载、DDR 等待、计算和写回；不包含 CPU 装载、轮询及完成跨域延迟。
ISSUES 包括零填充操作，流水排空不计入。两个计数器均为 32 位，超长任务会回绕，不能直接当作有效 MAC 数或加速比。

AI 任务错误码：1=零尺寸/通道；2=卷积配置/输出形状非法；3=超出 512 MiB；4=地址未对齐；5=输出覆盖只读区域；6=缓存/内部状态错误；7=量化控制或参数记录非法。
DMA 错误映射为 `8 | ddr_error_code`，其中 12=超时、13=写协议、14=读协议、15=初始化撤销。
提交前初始化已撤销时，CPU 邮箱可返回原来的错误码 8。
是否必须共同复位以 FAULT 为准；故障时已写出的结果不回滚。

## 6. 验证范围及复现

```bash
make test-ai-accelerator
```

三个验收层级：

- `test-conv-mac-tile`：21 次小块计算、84 个四路输出；检查权重复用、初始大部分和、连续供数、70 周期暂停、输出反压和复位。
- `test-conv2d-ddr`：16 个独立层配置加两次恢复重放，每组核对 838 个 128 位输出字；normal、随机停顿、零延迟三组均连接原样 `ddr3.sv`。逐拍检查原生 W 数据，读回比较，并检查输入/权重/偏置和输出边界哨兵未改变。另覆盖 10 个非法配置、计算中共同复位、原生超时与恢复。
- `test-ai-cpu`：真实 RV32I 程序用窗口装载输入/权重、提交 3×3 与 1×1 两种独立任务、读回比较，覆盖 Cin=17、Cout=5、尾部填充和跨列。CPU 25 MHz 与 50 MHz（DDR 随机停顿）均通过。另有 AI 故障跨域返回、故障期间窗口禁止抢占、IP 运算中共同复位和恢复测试。

以上“16 个层配置”和原始“两种任务”是独立任务。2026-10-26 新增 INT8 量化单元和 DDR 对拍，以及真正连接的 CPU 两层样例；详见 [新增验证](quantization_int8.md)。
Python `conv2d_reference.py` 是独立整数参考；RTL 只按物理布局取数，不能反过来用被测运算生成期望值。
CPU 样例指令段为 1568 字节；权重没有编入 ROM，程序在运行时通过窗口生成并装载。

产物：`build/conv_mac_tile/`、`build/conv2d_ddr/`、`build/ai_cpu/`。
新计算链和开启 AI 的邮箱/外设路径通过 lint；原块搬运、CPU 窗口和串行卷积的既有回归通过。
原 CPU 功能回归复用 `make coremark ITERATIONS=1`，performance 和 validation 两组 CRC 均通过；单次迭代仅用于功能检查，不作为正式跑分。
后续原功能优先复用已有程序，新功能使用上述专门测试。
