# CPU 的 DDR 分块访问窗口

状态：已完成 RTL、跨时钟行为仿真和 RV32I 裸机读写回归；尚未完成 PDS 综合、时序收敛及实板验证。

## 1. 接口结构

```text
CPU（当前 25 MHz，可调整）
  └─ dev_* 固定同步 MMIO
       └─ peripheral_bus
            └─ ddr_cpu_window
                 ├─ CPU 域：配置、状态、256 字节窗口
                 ├─ 请求/完成邮箱握手
                 └─ DDR core_clk 域：256 字节邮箱
                      └─ ddr_block_transfer（内部另有 256 字节块缓存）
                           └─ 紫光 DDR IP 原生用户接口
```

CPU 继续使用原来的 ROM/RAM。DDR 地址是相对于 DDR 起点的**字节偏移**，不是 CPU 可以直接解引用的地址。
访问 DDR 不增加 CPU 的普通访存等待周期：CPU 提交请求后继续执行自己的程序，通过状态寄存器轮询。

本阶段只允许窗口独占 DDR 原生端口；还没有接入 AI 引擎或多个 DDR 请求源的仲裁。

## 2. 寄存器与数据窗口

只支持对齐的 32 位 `lw/sw`，不支持字节或半字访问。未实现地址和不支持宽度的读返回零、写忽略。
寄存器与 UART 一样，在采样读请求的 CPU 上升沿更新 `dev_rdata`，没有额外插入一级读延迟。

| CPU 地址 | 名称 | 含义 |
| --- | --- | --- |
| `0x00031000` | CTRL | 写命令；读返回零 |
| `0x00031004` | STATUS | 只读状态 |
| `0x00031008` | ADDRESS | DDR 字节偏移 |
| `0x0003100c` | LENGTH | 本次搬运字节数 |
| `0x00031010` | ERROR_CODE | 只读错误码，低 4 位有效 |
| `0x00031100`～`0x000311fc` | DATA[0:63] | 256 字节数据窗口，每字 32 位 |

CTRL 按位定义：

| 位 | 含义 |
| --- | --- |
| 0 START | 写 1 提交；不需要软件再写 0 |
| 1 WRITE | START 同时为 1 时，1=窗口写入 DDR，0=DDR 读入窗口 |
| 2 CLEAR | 空闲时写 1 清除 DONE、ERROR、ERROR_CODE |
| 31:3 | 保留，忽略 |

STATUS 按位定义：

| 位 | 含义 |
| --- | --- |
| 0 BUSY | 请求已提交，结果尚未跨域返回；提交当拍即置 1 |
| 1 DONE | 最近一次请求成功完成，保持到下次提交或 CLEAR |
| 2 ERROR | 请求失败，配合 ERROR_CODE 判断 |
| 3 FAULT | DDR 原生接口发生致命故障，需要共同复位窗口和 DDR IP |
| 4 READY | DDR 初始化已同步到 CPU 域，且 BUSY=0、FAULT=0 |
| 5 INIT_DONE | 同步到 CPU 域的 DDR 初始化完成状态 |
| 31:6 | 保留，读零 |

注意：READY 表示可以提交下一条命令，不代表上一条成功。每次等待 BUSY 清零后，必须检查 ERROR 和 DONE。

- 地址、长度必须按 16 字节对齐，长度为 16～256 字节；默认 DDR 范围为 512 MiB。
- 长度/对齐/范围错误仍通过请求完成握手返回，未发出 DDR 原生命令。
- BUSY=1 时，所有配置、窗口写、再次 START、CLEAR 都忽略；窗口读返回零。
- 完成返回的那个 CPU 上升沿也按忙处理，软件应先读到 BUSY=0 再修改窗口。
- FAULT=1 后，配置和窗口写、START、CLEAR 均忽略；寄存器仍可读，BUSY=0、READY=0。
- 未初始化的窗口字读零；写 DDR 时尚未填过的窗口字也按零发送。
- 读取成功只替换 LENGTH 对应的窗口前缀，后面的字保留；软件只应消费本次有效长度。
- 数据按小端排列：DATA[0] 对应首个 128 位拍的 `[31:0]`，DATA[3] 对应 `[127:96]`。

## 3. 错误与复位

| ERROR_CODE | 含义 | 恢复方式 |
| --- | --- | --- |
| 0 | 无错误 | — |
| 1 | 长度为零或超过 256 | 修正参数后重新提交 |
| 2 | 地址或长度不按 16 字节对齐 | 修正参数后重新提交 |
| 3 | 地址区间超出 DDR 容量 | 修正参数后重新提交 |
| 4 | 原生接口长时间没有进展 | FAULT；共同复位 |
| 5 | 原生写 ID 或末拍标志错误 | FAULT；共同复位 |
| 6 | 原生读 ID 或末拍标志错误 | FAULT；共同复位 |
| 7 | 执行中的 DDR 初始化完成信号撤销 | FAULT；共同复位 |
| 8 | DDR 尚未初始化，或请求跨域后、发出原生命令前初始化撤销 | 等初始化后重试 |

超时参数 `DDR_TIMEOUT_CYCLES` 默认 4096，单位为 DDR `core_clk` 周期，检查连续无进展时间。
如果 DDR 时钟本身停止，DDR 域看门狗也停止，软件应另设轮询次数上限。

故障返回后 BUSY 清零只是允许 CPU 查看结果，底层搬运器仍然锁定。不能仅清状态、仅复位窗口或仅重启 CPU 来取消旧事务。
`rst_n` 必须同时复位本模块和 DDR IP；复位可能留下部分已写入的数据，软件应重新装载受影响的块。

## 4. CPU 调用顺序

**写 DDR：** 等 READY → 填 DATA → 写 ADDRESS、LENGTH → CTRL=3 → 等 BUSY=0 → 检查 DONE/ERROR。

**读 DDR：** 等 READY → 写 ADDRESS、LENGTH → CTRL=1 → 等 BUSY=0 → 检查 DONE/ERROR → 取 DATA。

完整裸机例子在 `csrc/software/ddr_window_test.c`：覆盖全部合法长度、高地址、跨列、清空窗口后读回及非法长度。
测试编译为 RV32I，指令段为 696 字节，使用原有 32 KiB ROM，不要求把模型权重编入 ROM。
真实模型的加载和调度程序体积要在后续集成时另外测量。

## 5. SoC 接入及频率调整

`peripheral_bus` 和 `soc` 都增加了 `ENABLE_DDR`，默认 0，保留原 UART 工程的可选配置。
使用时设置 `soc #(.ENABLE_DDR(1), .CLK_FREQ(25_000_000))`，并连接：

- `clk`：CPU 时钟，当前 25 MHz。
- `core_clk`：真实 DDR IP 输出的用户时钟，不能用 CPU 时钟冒充。
- `ddr_init_done`：真实 IP 输出的初始化完成信号。
- 全部 `axi_aw* / axi_w* / axi_ar* / axi_r*`：与 DDR IP 对应用户端口连接。
- `rst_n`：协调窗口和 DDR IP 的共同复位，实际板级复位/PLL 锁定逻辑由外层处理。

SoC 没有在内部实例化仿真的 `ddr3.sv`，也不包含物理 DDR 引脚和板级约束；真实 IP 由 FPGA 顶层实例化。
仿真中由测试台实例化原始行为模型连接这些端口。

提高 CPU 频率时，修改时钟来源、时钟约束和 `CLK_FREQ`；`CLK_FREQ` 用来计算 UART 波特率，不生成 CPU 时钟。
窗口协议不依赖 CPU/DDR 的整数频率比。25 MHz、50 MHz 和 CPU 高于 DDR 频率的仿真均有覆盖；这些不等于 CPU 已达到相应实板最高频率。

## 6. 跨域实现与约束要求

本版本使用小容量寄存器邮箱，避免依赖某个厂家双时钟、不同位宽 RAM 的推断规则。
两边各有 256 字节数据寄存器，底层另有 256 字节块缓存，总计 768 字节数据容量，另加控制寄存器。
实际寄存器、RAM、LUT 资源用量以 PDS 综合报告为准。

- CPU 提交时翻转 `request_toggle`，冻结地址、长度、方向、有效字标记和 CPU 缓冲。
- 请求翻转位经 `req_meta → req_sync` 两级同步，DDR 域再采样稳定的多位邮箱。
- DDR 域收齐结果后翻转 `ack_toggle`，保持结果缓冲和响应字段。
- 完成位经 `ack_meta → ack_sync` 两级同步，CPU 再复制稳定结果并结束 BUSY。
- 复位异步置位、各域两级同步释放。初始化完成信号也单独两级同步到 CPU 域。

**上板时需要完成时序约束，不能仅把两个时钟域的全部路径设成 false path。**

1. 为 CPU 与 DDR 用户时钟建立正确的时钟约束，并让工具保留上述同步链。
2. 仅对进入同步器第一级的异步控制路径作相应 CDC 例外；同步链级间仍需正常时序检查。
3. 为稳定邮箱路径设置数据路径最大延迟：CPU 配置/缓冲/有效位 → DDR 邮箱寄存器，建议不超过一个 DDR 用户时钟周期；DDR 结果缓冲/响应字段 → CPU 结果寄存器，建议不超过一个 CPU 周期。
4. 如果使用异步时钟组约束，检查它的优先级不会屏蔽邮箱的最大延迟检查；用 PDS 时序报告确认实际覆盖了寄存器路径。

这些邮箱路径是有握手保护的多位 CDC，不应把每个数据位分别打两级同步。行为仿真能验证握手逻辑，不能模拟亚稳态或证明物理布线延迟合格。
具体约束中的层级名和命令应按最终 FPGA 顶层及 PDS 版本填写，当前没有提交未经实现验证的板级约束文件。

## 7. 回归

```bash
make test-ddr-cpu-window
make test-ddr-block-transfer
```

`Iverilog/TB_ddr_cpu_window.v` 同一环境分别接外设接口和完整 SoC，DDR 始终连接未修改的 `vsrc/ddr3.sv`。
`scripts/test_ddr_cpu_window.py` 复用独立线性字节参考向量，结果保存在 `build/ddr_cpu_window/result.json`。

已验证：

- 每组外设测试 342 条有效命令、5952 个 32 位读结果，与 Python 参考及原生 W 数据分别核对。
- 不连续地址、局部覆盖、全部合法长度、跨 2 KiB 列边界、512 MiB 顶部地址。
- CPU/DDR 频率：25/约 131.25 MHz、50/约 131.25 MHz 并随机停顿、约 166.67/80 MHz 并零读写延迟。
- 初始化前提交、非法长度/对齐/范围、非法访问宽度、忙时写保护、状态清除、未初始化窗口按零处理。
- 空闲复位、AW 等待期间共同复位、超时故障跨域返回、CLEAR 无法解除 FAULT、共同复位后再次读取。
- 默认关闭 DDR 时状态地址读零、原生端口无请求且 UART 状态仍正常。
- 真实 RV32I 程序在 CPU 25 MHz、50 MHz（DDR 随机停顿）下运行，每组完成 16 次写入/读回/比较。
- 新窗口及底层搬运器通过严格 Verilator lint。
