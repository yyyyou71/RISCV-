# 可配置边缘 AI 加速器实施计划

日期：2026-10-24  
状态：第一至第五步的当前支持功能已完成行为仿真验收，包括 DDR 任务表和同固件执行不同网络；完整检测网络及实板验证尚未完成
目标平台：RK3568_MES2L100H 的 FPGA 部分  
时间约束：距比赛结束约十天

## 一、目标与范围

设计一个由自研 RISC-V CPU 调度的可配置 CNN 加速外设。
CPU 保留自己的 ROM 和 RAM；DDR 保存模型、任务表、图像和推理中间结果。
CPU 可以显式访问 DDR，但暂不将其作为常规堆、栈或取指存储。

在引擎支持的算子、数据类型和尺寸范围内，通过更换模型资产和任务表运行不同网络，不需要重新设计或综合计算硬件。

模型资产包括：

- 权重、偏置与量化参数。
- 各层尺寸、通道数、卷积参数与连接关系。
- DDR 存储布局和执行任务表。
- 输出格式与后处理所需配置。

新增不支持的算子可能需要扩充硬件；更换检测头形式也可能需要更新 CPU 后处理固件。
第一版不承诺支持任意 YOLO 或所有神经网络。

十天内优先保证正确性、可配置性和可演示性，再根据实测结果优化性能。

## 二、当前基础

- 自研五级流水线 CPU 已完成 CoreMark，用户已验证 CPU 和 UART 上板运行。
- CPU 当前使用 32 KiB ROM、64 KiB RAM。
- 现有外设接口使用固定同步读时序，没有可变延迟等待握手。
- 用户的 `../materials/ziguang-fpga2` 工程已完成真实 DDR 顺序读写。
- 已核对其中 DDR IP 与 `vsrc/ddr3.sv`：85 个端口、7 个参数声明匹配。
- 原读写控制器与行为模型在功能级 FIFO 替身下通过三组定向回读测试；这不替代真实 FIFO、PHY 和实板验证。
- SPI 由其他人负责，本任务预留接入接口，开发初期用 testbench 装载数据。
- ARM 只作为文件和消息转发端；推理及其后处理由自研系统完成。比赛规则对这一职责划分的认定仍需按完整细则确认。

## 三、整体结构

```text
自研 RISC-V CPU ── 自己的 ROM / RAM
       │
       ├─ 配置和状态寄存器 ── AI 计算引擎
       │                          │
       └─ DDR 分块访问窗口 ────────┤
                                  ↓
                          通用 DDR 块搬运模块
                                  ↓
                                DDR3
```

CPU 负责装载、任务调度、状态检查与首版检测后处理。
计算引擎负责自行读取输入和权重、执行计算、写回结果。
CPU 不逐个给 MAC 喂数据，也不保存完整模型和特征图。

## 四、第一步：通用 DDR 块搬运模块

建议模块名：`ddr_block_transfer`。

借鉴第三个工程的完整突发缓存、预取和握手机制，去除视频 SOF、帧槽和整帧提交协议。

### 第一版接口范围

| 方向 | 内容 |
| --- | --- |
| 命令输入 | 起始字节地址、长度、读或写、启动 |
| 状态输出 | 忙、完成、错误 |
| 数据 | 待写入数据块、读回数据块 |

第一版约束：

- 起始地址按 16 字节对齐，长度为 16 字节的整数倍。
- 单次最多 256 字节，大数据由软件或上层控制器循环分块。
- 一次只执行一个读或写命令。
- 只在空闲时接受命令，并锁存其参数。
- 发写命令前备齐整段写数据；发读命令前预留整段接收空间。
- 根据实际接受的数据拍与末拍标志完成任务，不假设固定 DDR 延迟。
- 明确完成和错误状态的保持、清除方式。

### 地址与时序

当前 x16 配置下，一拍 128 位，即 16 字节，对应原生地址增加 8。
上层统一使用字节地址，搬运模块负责转换为原生地址。
256 字节对应原生地址跨度 128，不能直接沿用视频工程每个突发地址加 256 的公式。

内部需在列边界拆分请求。默认列宽 10 位，对应 2048 字节边界。
写侧没有 WVALID，读侧没有 RREADY；写数据必须预先准备，读数据必须全部接收。

### 验收

- 不同地址写入并读回，数据逐项一致。
- 正常延迟、零延迟、地址握手停顿、写停顿、读数据空泡下均正确。
- 覆盖跨列拆分、高地址、忙时重复启动和复位中断。
- 先行为仿真，再接真实 DDR IP 尽早上板。

## 五、第二步：CPU 的 DDR 分块访问窗口

增加一个小容量 MMIO 数据窗口，初步按 256 字节设计。
对 CPU 的寄存器与窗口读访问保持现有固定同步读时序，DDR 延迟由外设内部处理。

写入流程：

```text
CPU 填充窗口 → 配置 DDR 地址和长度 → 启动写入 → 轮询完成
```

读取流程：

```text
CPU 配置 DDR 地址和长度 → 启动读取 → 轮询完成 → 读取窗口
```

这一阶段暂不修改 Acore 流水线以支持普通 DDR load/store。
CPU 可以通过窗口分块访问 DDR，但不能把 DDR 地址直接当成普通 C 指针。

### DDR 使用权

第一版按阶段互斥：

1. 装载阶段：CPU 使用 DDR，计算引擎空闲。
2. 计算阶段：引擎使用 DDR，CPU 从自己的 ROM/RAM 执行并轮询 MMIO。
3. 完成阶段：所有在途访问排空后，将使用权交回 CPU。

CPU 的控制和状态寄存器访问不因 DDR 使用权而阻塞。
跨时钟命令、完成事件和数据缓冲必须有可靠握手或 FIFO，不能直接跨域传递一拍启动信号。

### 验收

裸机程序完成“写窗口 → DDR → 清窗口 → 读回 → 比较”，覆盖多块与不同地址。
忙时操作、使用权切换、完成状态和错误状态行为明确。

## 六、第三步：可配置卷积计算核心

先独立验证小规模 MAC 阵列，再组成完整卷积。
先保证低并行度版本正确，再根据综合资源和时序扩大阵列。

第一批支持：

- 1×1、3×3 卷积。
- 可配置输入、输出通道数。
- stride=1/2、padding=0/1。
- 偏置、明确的移位量化规则。
- ReLU 或激活旁路。

输入/输出通道不足并行组时补零；跨多个输入块计算同一输出时保留完整部分和。
输入缓存、权重缓存、部分和与输出缓存分别规划，第一轮先用单缓冲。

### 数值格式

数值格式与首个可复现模型一起冻结。原始卷积基线默认 W8A8，另对拍 W8A16/W9A16；位宽为综合参数，层尺寸为运行时配置。
串行数学基线输出 64 位原始累加结果；并行 DDR 引擎已增加逐输出通道重定标和可选 ReLU，详见 [INT8 量化与层间连接](quantization_int8.md)。
当前 ABI 尚未与具体检测模型完成匹配，不代表任意已量化模型可直接导入。
若采用 CNN_FPGA 的现成 MAT，必须保留其至少 9 位有效权重及原有舍入、钳位规则，不能直接截为 INT8。
初期可以使用 16 位容器保存数据，接受一定存储和带宽开销，避免为了缩窄位宽临时重训。
累加器和缩放乘法位宽根据取值上界确定，不能依赖隐式截断。

### 验收

与 Python 整数参考逐项一致，覆盖符号、边界值、空泡、通道补齐、首次/末次累加和量化舍入。

## 七、第四步：单层 DDR 计算闭环

```text
DDR 输入和权重
    ↓
搬运到片上缓存
    ↓
卷积、偏置、量化、激活
    ↓
结果写回 DDR
```

验收包括不同尺寸、不同通道数、1×1/3×3、stride、padding，以及多块部分和累加。
按数据值对照整数参考，不能只以仿真正常结束作为通过依据。
尽早进行单层上板验证，分别记录搬运、计算与等待周期。

## 八、第五步：CPU 执行网络任务表（仿真验收完成）

一条任务至少描述：

- 操作类型。
- 输入、权重、偏置和输出地址。
- 高宽、输入/输出通道数。
- 卷积核、步长和 padding。
- 量化与激活参数。

CPU 调度流程：

```text
取任务 → 配置引擎 → 启动 → 等待完成 → 下一条任务
```

权重和任务表放 DDR。CPU 每次读取少量描述符，不随模型规模增加大量专用程序代码。
PC 工具提前安排数据地址和生命周期，第一版不做动态显存分配器或 CPU 端通用模型解析器。

### 通用性验收

同一计算 RTL/位流，在运行时加载两份不同配置的网络，层数或通道数发生变化，各自输出与参考一致。
仅改变综合参数、重新生成位流，不算完成运行时可配置目标。

2026-10-26 验收：已实现 64 字节任务描述符、模型头、PC 打包工具及通用 RV32I 执行器。
同一固件/RTL 在一次运行中处理两层、三层和引用较早层输出的网络，另覆盖描述符拒绝、引擎报错及恢复；25/50 MHz 和 DDR 停顿/零延迟均通过。
任务、输入、权重和所有中间结果均在 DDR，CPU 每次只缓存少量记录；详见 [任务表 ABI、接口与仿真](ai_task_runtime.md)。

## 九、同步工作：尽早确认首个检测模型

模型验证从第一阶段同步开始，不能等硬件完成后再选模型。

优先检查 CNN_FPGA 已有的量化权重、样例输入、逐层输出和后处理，尝试复现完整检测结果。
它是专用小网络，不能将其资产按标准 YOLOv5/11/26 格式处理。
若前两天无法建立可信的软件参考，应尽早调整模型候选。

模型确定后，再补它实际需要的 COPY、池化、ADD、上采样、SiLU 等操作与后处理。
YOLO 版本名不作为基础搬运、配置接口和 MAC 设计的前提。
第一版优先静态图片检测；摄像头、显示与同帧画框在基础闭环稳定后接入。

## 十、ROM、RAM 与外部装载

| 内容 | 存放位置 |
| --- | --- |
| CPU 驱动、调度、简化后处理代码 | ROM |
| 栈、状态、少量收发和任务缓存 | CPU RAM |
| 模型权重、量化参数、任务表 | DDR |
| 图像、特征图、检测头输出 | DDR |
| 当前计算块和部分和 | 加速器片上缓存 |

当前链接脚本将 .rodata 放到 RAM，不能把大权重数组写进 CPU 固件。
每一步检查 ELF/map 的 ROM 和 RAM 占用，必要时再扩大 ROM。
SPI 实现由他人负责，约定块长、字节序、地址、长度、流控、CRC 和完成/错误状态即可。
本任务先使用 testbench 注入数据，后续接入实际 SPI 模块。

## 十一、十天检查点

以下是工作安排，不是完成时间保证；以已有 CPU 与真实 DDR 上板基础为前提。

| 时间 | 应达到的结果 |
| --- | --- |
| 第 1～2 天 | CPU 可靠分块读写 DDR；首个模型的软件参考可信 |
| 第 3～5 天 | 单层可配置卷积完成 DDR 读入、计算、写回与逐项对拍 |
| 第 6 天 | CPU 多层调度；同硬件验证不同网络配置 |
| 第 7～8 天 | 完整小检测模型、后处理与外部加载集成 |
| 第 9～10 天 | 板级稳定性、时序、性能记录与演示整理 |

每个主要阶段都尽早上板，不把实板问题集中到最后一天。
如果第 4～5 天仍没有可靠的单层闭环，停止增加复杂算子、并行度和实时视频，优先解决存储与计算正确性，并明确报告完整检测的剩余缺口。
