# INT16 5×5最大池化与SPPF验证

日期：2026-10-27。状态：独立DDR池化及CPU任务表对拍通过；尚未综合或上板。

## 1. 运算和数据流

每个输出位置、每个通道独立取周围5×5邻域的最大值。
固定窗口5、步长1、填充2，因此输出仍为H×W×C。
按有符号INT16比较，初值为-32768；跳过图像外位置，相当于用INT16最小值填充。
全负数的边界结果不会被错误地变为0，输入为-32768时也原样保留。
不做量化、缩放、ReLU或饱和，输出沿用输入尺度。

```text
CPU提交地址、H/W/C
  → DDR引擎遍历输出位置和每组8通道
  → 读取各有效邻居的16字节数据
  → 8个有符号比较器更新当前最大值
  → 写回一个16字节输出字
  → 完成后CPU继续提交下一条任务
```

RTL位于`vsrc/conv2d_ddr_engine.v`，复用现有`ddr_chunk_client`和`ddr_block_transfer`。
CPU仍访问本时钟域寄存器并轮询完成，DDR原生等待由后台状态机处理，不要求CPU一拍完成DDR读写。

## 2. 存储和资源取舍

输入、输出都为HWC-align16(C)，每元素2字节，物理大小为：

```text
H × W × align16(C) × 2字节
```

池化数据路径只需一个128位最大值寄存器、窗口/通道计数和地址寄存器；仍使用共用DDR客户端缓冲。
每次同时比较同一像素的8个通道，与16字节DDR数据字对应，不增加卷积MAC或乘法器阵列。
不引入整图缓存、行缓存或RAM IP，实际新增资源与最高频率仍以PDS综合结果为准。

邻居地址通过逐列/逐行加法推进，不在每次读数据时重新计算像素索引乘通道间距。
无效空间位置不发起DDR读取；完全属于通道填充的8通道组也不读DDR，输出显式写零。
部分有效的最后一个数据字读取后，仅保留有效通道，填充位置仍清零。

当前不同输出窗口会重复读取重叠邻域。内点每组8通道需要25次16字节读取和1次16字节写入。
这是先保证正确性的小缓存实现；后续可增加行缓存减少重复读取，尚未实现读算重叠或层间融合。

## 3. MMIO与任务表

沿用既有寄存器和CDC邮箱，不增加外部端口或邮箱字段。

| 寄存器 | MaxPool5含义 |
| --- | --- |
| AI_OPCODE（0x30248） | 4 |
| AI_INPUT（0x30208） | 输入DDR字节地址 |
| AI_OUTPUT（0x30214） | 输出DDR字节地址 |
| AI_HW（0x30218） | 低16位H、高16位W |
| AI_CHANNELS（0x3021c） | 低16位Cin、高16位Cout，二者相等 |
| AI_POST（0x30238） | 4，表示INT16格式，不执行Q13量化 |
| AI_WEIGHT、AI_BIAS、AI_QUANT、AI_GROUP、AI_CONV | 必须为0 |

H/W/C范围为1..65535，输入输出16字节对齐，整个物理张量须在512MiB DDR内。
输出禁止与输入重叠，包括部分重叠；不支持原地池化。
只支持综合配置`AI_ACT_WIDTH=16`，8位硬件拒绝操作码4。

错误码沿用引擎：1尺寸、3范围、4对齐、5重叠、7格式或未使用字段错误；原生DDR错误继续向上传播。
所有配置在接收START时锁存；DONE等最后一笔DDR写入完成后才置位。
`mac_issues=0`，`cycles`统计整个池化任务。原生FAULT后需按原规则共同复位引擎和DDR接口。

AIM1版本2继续使用64字节任务：opcode=4，word7的Cin/Cout相等，word10/11等于输入H/W。
除输入、输出、尺寸、POST及操作码外，权重/偏置/量化/分组/卷积字段均为0。
CPU先检查全部描述符，再执行；输入可以来自初始图像或先前任务，输出只能放在模型工作区。

JSON只需：

```json
{"name":"pooled","op":"maxpool5","input":"previous_layer"}
```

打包工具自动推导形状、尺寸和地址，不接受另外传入kernel/stride/padding等字段。
后续卷积直接以`input="pooled"`读取DDR结果，不需要CPU复制。

## 4. 验证与复现

```bash
make test-ai-maxpool
# 只生成C资产、任务包、固件和RTL仿真程序：
python3 pc_ai/verify_w8a16_tasks.py --suite maxpool --prepare-only
# 扩展CPU/DDR时钟组合，可由用户运行等待：
python3 pc_ai/verify_w8a16_tasks.py --suite maxpool --profiles all
```

输出集中在`pc_ai/outputs/maxpool_tasks/`，报告为`result.json`。
`pc_ai/export_maxpool_tasks.c`直接调用参考工程的`maxpool5`、`conv_layer`、`concat2`、`add_point`。
Python仅打包、启动仿真和比较，不另写一套池化数值参考。

已通过默认定向检查：

- 16种独立DDR配置，涵盖1/5/8/9/15/16/17/31/32/33/192/384通道、单点、单行、单列及含5×5内部位置的特征图。
- 随机正负数、全负数、全-32768、全32767；输入填充置32767，输出预填非零毒值，检查尾部显式清零。
- 输入位于DDR地址0、输入或输出恰好结束于512MiB上界、跨2KiB列边界；只读区和输出哨兵不变。
- 每个原生写拍、最终输出、输出高宽、零MAC计数，以及实际DDR读次数均检查；池化读取不得越过输入区域。
- 21种非法配置在任何DDR操作前拒绝，包括空尺寸、通道不符、地址不齐/越界/重叠及无效字段。
- 读取过程中共同复位，原生读地址超时、写地址超时锁定，联合复位后重新执行通过。
- DDR正常、随机停顿、零读写延迟三组均通过；每组检查746个128位输出字，其中包含3次重放。
- 同一CPU固件一次处理23份模型请求、15次AI提交，核对17020个DDR字；19种错误与不复位重跑均通过。
- 参考完整SPPF的5条任务：cv1→MaxPool5→Concat(cv1,pool)→cv2→ADD(原输入,cv2)。使用真实参数和1×1×384输入，导出图最终值另与原`sppf_fwd`核对。
- 另用3×5空间尺寸验证卷积→池化→卷积，以及两次连续池化；CPU只写报告，全部中间图由引擎写回。
- 原生FAULT停止、8位硬件拒绝16位模型包均通过；8/16位引擎及16位外设总线严格Verilator lint通过。

池化阶段统一RV32I固件指令段4104字节；加入上采样后的4244字节固件也已重跑本套检查通过。初始化数据段0字节，未将模型资产放入32KiB ROM。
受共用打包/调度修改影响的Concat/C3与W8A8任务表检查也已重跑通过，三套测试产生的4104字节固件SHA256一致；未重复运行CoreMark。
默认CPU任务时钟25MHz、DDR用户时钟约131.25MHz；扩展时钟组合的实际执行情况以报告为准。
完整SPPF的小图验证不等于完整检测网络或精度验证；真实IP、物理CDC约束、PDS与上板仍待完成。
