# INT8 层间输出、量化 ABI 与两层连续计算

日期：2026-10-26。

本阶段在原有 4×2 卷积通路之后加入逐输出通道重定标、可选 ReLU 和 HWC INT8 写回。
CPU 已能连续提交两层任务，第二层直接读取第一层在 DDR 中的输出。
这是整数算子和存储接口验证，尚未选定并运行完整检测模型；没有替换既有模型的激活函数或宣称检测精度。

## 1. 数值规则

输入、权重和层间输出均采用有符号 INT8，零点为 0。
输入激活采用每张量尺度，权重可以采用逐输出通道尺度。
偏置必须预先转入输入×权重的累加尺度。BN 折叠、尺度选择和参数导出由离线工具完成，CPU 不做逐元素浮点缩放。

对输出通道 c：

```text
acc = Σ(input_int8 × weight_int8) + bias_int32
ratio[c] ≈ multiplier[c] / 2^shift[c]
scaled = round_nearest_ties_away_from_zero(acc × ratio[c])
activated = relu_enable ? max(0, scaled) : scaled
output = clamp(activated, -128, 127)
```

`ratio` 应由模型导出的 `input_scale × weight_scale[c] / output_scale` 近似得到。
相邻两层必须使用同一个中间张量尺度；把字节布局接通并不自动保证模型尺度正确。
`multiplier` 为 0..2^31−1，`shift` 为 0..95；零倍率允许输出常零。
这套规则是当前硬件 ABI，不保证与任意框架的默认舍入、零点和激活定义一致，导出时必须核对。

示例：倍率 1、右移 1 时，`+5 → +3`、`−5 → −3`；结果超过范围时饱和，而非丢弃高位。
全部输入通道块完成累加后才执行一次量化，不能在每个 16 通道块结束时提前舍入。

`requant_int8.v` 使用一条重定标通路，四个输出通道分时使用。
完整保留 96 位绝对值乘积，避免 INT64×INT32 后先截断导致错误；正负数统一在绝对值域舍入。
接收输入后下一拍寄存输出，`out_valid` 保持到 `out_ready`；配置随输入握手锁存，复位丢弃在途结果。
它使用 RTL 乘法表达式，没有例化新的厂商量化乘法 IP；APM 映射、资源和时序仍需 PDS 验证。

ReLU 只是当前支持的可选激活。SiLU、LeakyReLU、任意非零 zero_point 和残差相加尚未实现。
对于需要这些操作的模型，应补相应算子及整数参考，或重新训练兼容网络，不能直接改激活并沿用权重冒充等价结果。

## 2. CPU 配置和 DDR 参数表

原来的 AI 寄存器和原始 INT64 输出模式保留，增加：

| 地址 | 名称 | 定义 |
| --- | --- | --- |
| `0x30238` | AI_POST | bit0=INT8 输出；bit1=ReLU；其余位必须为 0 |
| `0x3023c` | AI_QUANT | 逐输出通道参数表的 DDR 字节地址，16 字节对齐 |

`AI_POST=0` 为原始 INT64 输出，忽略 AI_QUANT；`1` 为 INT8 输出/激活旁路；`3` 为 INT8+ReLU。
`2` 或带保留位的值返回错误 7。
两个寄存器复位为零；忙时写入忽略，与其余配置一起通过稳定邮箱跨域。
上板时的多位邮箱最大延迟约束必须覆盖新增 `ai_post`、`ai_quant`。

每通道 16 字节，小端：

| 字节偏移 | 内容 |
| --- | --- |
| 0..3 | u32 multiplier，最高位必须为 0 |
| 4..7 | u32 shift，必须为 0..95 |
| 8..15 | 保留，必须为 0 |

表按 `align_up(Cout,4)` 条分配。硬件每个 4 输出通道组读取一次参数，在整组所有像素间复用。
无效输出通道不读取参数，内部设为零；导出端建议仍将填充记录置零。
量化表也受 DDR 容量、对齐及输出禁止覆盖只读区域的检查。

非法记录返回错误 7；对齐、范围、重叠分别沿用 4、3、5。
记录按组读取，后面组的非法记录可能在前面组已写出后才被发现：此时 ERROR=1、DONE=0，不回滚部分输出。
这类数值配置错误不触发原生 DDR FAULT，可清除后重提；原生超时等故障仍需共同复位。

## 3. 可直接连接下一层的物理布局

权重仍为 `align4(Cout)-KY-KX-align16(Cin)`，偏置按 align4(Cout) 分配。
INT8 输出改为 `Hout-Wout-align16(Cout)`，每个像素的尾部通道全部写零：

```text
output_pitch = align_up(Cout, 16)
byte_address = output_base + (y*Wout+x)*output_pitch + channel
allocation_bytes = Hout*Wout*output_pitch
```

下一层的输入基地址设为本层输出地址，输入高宽设为本层输出高宽，Cin 设为本层实际 Cout。
这样输入地址公式完全相同，CPU 不需要读取、复制或重排中间特征图。
下一层权重的输入通道维也必须按本层实际 Cout 补齐到 16。

硬件一次只产生 4 通道，第一版按以下方式组成 16 字节拍：

1. 每个像素、每个 16 通道块的第一组，从全零字开始插入本组 4 个字节并写回。
2. 后续三组先读已写的字，替换本组 4 字节，再完整写回。
3. 最后不足 4 通道的字节以及未使用组保持为零。

不依赖 DDR 原内容，也不要求 CPU 预先清零输出。
这采用现有搬运器的完整拍读写，每个有效 4 通道组写一次，除每 16 通道的首组外还读一次。
因此它有额外 DDR 流量，尚未实现跨组拼满一拍、写掩码或双缓冲优化，也没有搬运与计算重叠。
输出区在引擎发布 DONE 前只能视为部分结果；现有单任务 DDR 所有权确保 CPU 不会在读改写期间介入。

逻辑张量从 INT64 变为 INT8，每个有效元素缩小 8 倍；物理容量还受 align4/align16 填充影响，不能一概声称整张图缩小 8 倍。
原始 INT64 模式的输出布局保持 `Hout-Wout-align4(Cout)`、每元素 8 字节，不能直接作为下一层 INT8 输入。

## 4. 验证和复现

```bash
make test-requant-int8
make test-conv2d-quant
make test-ai-cpu
# 包含原始 INT64 回归和缓存/IP 测试：
make test-ai-accelerator
# 原 CPU 功能沿用既有程序：
make coremark ITERATIONS=1
```

- 量化单元：2852 组向量，包括 INT64 极值、零倍率、大倍率、0..95 位右移、正负半整数、饱和、ReLU、非法参数、输入配置变化、输出反压和乘积寄存后复位。
- DDR 量化：16 种独立层配置，覆盖 Cin 跨 16、Cout 跨 4/16、多个空间小块、padding、K=1/3、stride=1/2、逐通道倍率及偏置开关。输出区预填毒值，逐次检查原生写数据和最终结果，包含只读资产及边界哨兵检查。运行正常、随机停顿、零读写延迟三组。
- 异常：基础 10 种非法卷积配置，加 9 种非法量化配置/记录和一次后组记录错误，覆盖无写入拒绝与已经写出部分结果的错误状态；另验证量化中共同复位、DDR 超时锁定和复位恢复。
- CPU：保留原始两种独立单层任务；新增真正连接的两层 `3×5×17 → 3×5×5 → 2×3×3`。第一层 3×3/ReLU，第二层 1×1/stride2/激活旁路；第二层读第一层的 DDR 地址。测试台明确禁止 CPU 在两层间启动 DDR 窗口任务，之后检查两层结果和所有填充字节。25 MHz 与 50 MHz/DDR 随机停顿均通过。

两层测试程序 `csrc/software/conv2d_chain_test.c` 使用 RV32I，指令段 2764 字节；原始测试为 1568 字节。
权重和量化参数由测试程序生成并通过窗口装入 DDR，没有把整模型编入 ROM。
Python `quant_reference.py` 同时提供独立整数参考、HWC 打包和参数记录导出函数；还不是完整模型量化/校准或模型编译器。

日志和向量分别位于 `build/requant_int8/`、`build/conv2d_quant/`、`build/ai_cpu/`。
这里的 16 种配置是独立测试，只有 CPU 的两层样例实际连接。
CoreMark 单次迭代只用于 CRC 功能回归，不是正式跑分。

## 5. 接下来

确定可复现的检测模型、预处理和逐层整数参考，核对本 ABI 能否表达其尺度和激活，再补实际所需算子和任务表驱动。
同时推进真实算术 IP 对拍、PDS 资源/时序、邮箱约束和真实 DDR 上板验证。
