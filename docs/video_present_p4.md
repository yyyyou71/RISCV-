## 数据路径与所有权

同一次 HDMI SOF 抓取原图和 96×96 张量，继续使用已有匹配的 frame_id 和原图槽位。
99 任务推理和 CPU 后处理结束后，如果 PCIe 已连接，CPU 读取置信度排序结果的前 16 条，
把模型坐标缩放回 1920×1080 并裁剪；无效或完全越界的框跳过，不以第 17 条补位。
SPI 的 results 仍能分页取回全部检测记录，上限 300。当前后处理沿用主线 Top-K，**没有新增 NMS**。

CPU 只写框坐标、颜色、帧号和槽号，不搬运整张图像。DDR 用户时钟域再次核对帧号、有效位和
已有的原图持有位，确认槽位不处于写入中，才启动原参考工程的 DDR 读控制器。
新增 rgb565_box_overlay 在 DDR 读回与原 PCIe 异步 FIFO 之间流水画框：每拍 8 个 RGB565 像素，
三层寄存器，16 框，2 像素边框；重叠处高置信度框优先，颜色由类别选择。只画矩形边框，没有字符标签。
原始 DDR 数据不被修改，图像仍为完整 1920×1080 RGB565，共 4,147,200 字节。

原 PCIe IP、DMA、字节序转换、FIFO 预取流水和 DDR 地址布局保留。
新增控制器在 PCIe 域数满 259,200 个 128-bit 数据、DMA 不忙、FIFO/预取流水全空，且 DDR 读完成后，
才报告 DONE 并解除本次发送附加的槽位保护；原来的抓帧持有位仍由 video-release/retry 释放。
DONE 表示 FPGA 侧数据交付和 DMA 流水已排空，不等同 RK 已校验并显示图像。
每次读取会消耗该槽的 available 标记，因此下一次发送需要 video-retry 取得新帧；不支持重复发送同一槽。

发送中不接受换帧、释放、模型装载或新推理。PCIe 中途断链或数据欠载会锁住该槽并报告错误，
需要 FPGA 全局应用复位恢复，避免仍有事务时复用帧或清空共享 DDR 仲裁器。
没有 RK 时，PCIe 读控制器不发起读事务，CPU/DDR/视频自检仍使用原独立复位路径。

## RK 联调入口

在 RK 本机 `make clean`、`make all`；WSL 本次生成的 x86 文件不能拿到 ARM 上运行。

```sh
./rk_comm_cli /dev/spidev4.0 video-status
./rk_comm_cli /dev/spidev4.0 present-status
./rk_comm_cli /dev/spidev4.0 present
```

present 不需要已加载整网模型：有持有原图时可以先用 0 框验证原图链路；如有同帧 DONE 的整网结果则使用前 16 框。
模型推理结束后，PCIe 已连接会自动排队一次画框帧；未连接时跳过自动排队，连接后也可手工 present。
CPU 只准备 FIFO，**RK 仍必须按桌面参考工程的方式启动 PCIe DMA，收取完整 4,147,200 字节**。
SPI present 返回接收成功不代表图像已发完，需要轮询 present-status。
RK 接收程序和驱动尚未在本轮接入验证；现有桌面已跑通链路的 DMA 配置应继续使用。

## MMIO：0x30900

| 偏移 | 用途 |
|---|---|
| 00 | 写 1 启动，写 4 清完成/错误标记 |
| 04 | bit0 busy，1 done，2 error，3 PCIe ready，4 功能存在，5 locked |
| 08 / 0c | 期望 frame_id / 原图槽 0..4 |
| 10 | 框数 0..16；写入时清空框有效位，所以必须先写框数 |
| 14 | 框索引 0..15 |
| 18 / 1c | 起点 / 终点：x[10:0]，y[26:16]，其余位写 0，坐标均为包含端点 |
| 20 | RGB565 颜色，写入提交当前框 |
| 24 | 错误：1 未就绪，2 参数，3 帧身份/持有不符，4 断链，5 欠载或超量 |
| 28 / 2c / 34 | 已受理帧号 / 128-bit 字数 259200 / 最大框数 16 |

SPI 扩展命令 16=present-status、17=present，均无请求载荷，返回 12 个 32-bit 字：
ABI、软件状态、软件错误、硬件状态、run_id、frame_id、槽号、框数、硬件错误、已受理帧号、总字数、最大框数。
软件状态 0 空闲、1 准备框、2 等 DMA、3 完成、4 错误；软件错误 1 结果读取失败、6 完成帧号不符，其他为硬件错误码。

## 布线耗时与量化路径

上一版 place_route/run.log 的布局布线墙钟时间为 1577 秒，约 26 分 17 秒。
布局 483.36 秒，全局布线 53.69 秒，详细布线 343.59 秒（132 轮），
布线器内保持时间修复 96.88 秒，布线后保持时间处理 140.20 秒；其余为准备和其他阶段。
用户观察到接近 40 分钟可能还包含综合、映射等阶段，不能把全部时间归为全局布线。
旧报告 DDR 用户时钟 131.25 MHz 最差 setup 为 -11.908 ns，CPU->DDR 配置验证也有长路径，
PCIe/SPI 仍有各自的负余量。旧资源/时序不是本次 P4 的实现结果。

本轮拆分 requant_q13 原先一拍内的 RHU、96-bit 两组求和、偏置、钳位、ReLU 和末级乘法。
精确 signed64×unsigned31 改由一个注册的 16×16 乘法器分 8 个部分积求和，
舍入、移位、求和和钳位也分别寄存；对外仍为 ready/valid，不改参数、数值格式和 MAC 厂商 IP。
这会增加每个输出的量化等待周期，属于面积/时序与速度的取舍，**没有宣称整网加速**。
未放松 DDR 时钟，未关闭 hold 修复，groute_seed 仍为 3。
是否缩短布局布线、是否改善最终时序，需要下一次 P&R 才能确认；本次没有完成新版本 P&R/位流。
