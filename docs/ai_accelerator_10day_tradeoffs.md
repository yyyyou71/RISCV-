# 实现可配置边缘 AI 加速外设的取舍

日期：2026-10-24。本文覆盖此前将 YOLOv5n 过早固定为最终目标的部分规划。
状态：需求与实现边界规划；本轮未新增加速器 RTL。

## 1. 已确认的条件

- 用户目标：自研 RISC-V 调度一个可更换模型的 AI 外设。
- CPU 保留自己的 ROM/RAM；DDR 是模型与推理数据的独立存储区域，CPU 可以访问，但不默认作为栈、堆或普通程序内存。
- 模型权重、量化常量、网络任务表与图像从外部装载进 DDR。
- CPU 与 UART 已由用户上板验证；真实 DDR 在 ziguang-fpga2 工程完成过顺序读写。现已审阅该工程并与行为模型核对，见 [DDR 核对报告](ddr3_usage_report.md)。重点复用其 IP 配置、时钟、引脚和读写握手方式。
- SPI 尚未由当前工程验证，但已有其他人负责；本任务只定义接入接口，不把 SPI 实现列入自己的关键路径。
- ARM 仅计划用于通信、文件传输和消息转发，不执行推理、解码或 NMS。
- 距比赛结束约十天；第一版优先静态图片、正确性和可配置能力，暂不承诺实时帧率。

用户报告的上板结果与本轮仓库检查分开记录：当前仓库只有 DDR 行为模型和基础 SoC 接口，本轮没有重新验证上述实板结果。

## 2. 核心建议

实现一个“有限算子集合、可由软件配置的 CNN 引擎”。
固定的是计算单元及其支持范围；可更换的是权重、量化常量、层数、通道数、尺寸、连接关系和任务表。
这符合可编程推理外设的方向，不要求第一版具备任意神经网络、任意算子、任意精度的能力。

十天内不建议同时增加通用 ONNX 运行时、任意网络编译器、复杂指令集、Cache、一致性、乱序 DMA、多模型并发和摄像头/显示全链路。

## 3. 更换模型真正需要更换什么

| 更换内容 | 需要更新的资产 | 第一版能否不改 RTL |
| --- | --- | --- |
| 同结构模型重新训练 | 权重、偏置、量化参数 | 可以，需满足支持的数值范围 |
| 改层数、通道数、图像尺寸 | 上述资产、任务表、存储布局 | 在算子/计数器/缓存分块范围内可以 |
| 增加分支与拼接 | 任务表、数据保留范围、COPY/ADD 等任务 | 前提是对应基础操作已支持 |
| 改检测头形式 | 任务表及后处理配置或固件 | 不一定需要改 RTL，但可能要改 CPU 固件 |
| 增加注意力/softmax 等当前不支持的算子 | 扩充硬件或软件路径 | 不能承诺只换模型资产即可 |

同一结构换权重，和更换整个网络结构，是不同层次的灵活性。
通用性验收应至少包含：同一计算 RTL/位流，在运行时加载两份不同配置的 CNN，层数或通道配置有变化，各自输出与参考一致。
不能只修改综合参数、重新生成位流，再把它称作运行时可更换模型。

## 4. 三种主方案

| 方案 | 优点 | 缺点和风险 | 十天内的定位 |
| --- | --- | --- | --- |
| A：移植固定网络全流水线 | 可以借鉴 CNN_FPGA 的完整处理链；低层间 DDR 流量 | 模型和节拍绑定；运行时改模型困难；PG2L200H 到 PG2L100H 的资源和引脚仍需重做 | 可作对照或已有移植成果的备选，不适合作为当前通用目标的主线 |
| B：CPU 调度、有限算子复用引擎 | 符合用户目标；硬件规模可控；模型和任务表放 DDR | 需要可靠搬运、缓存、整数参考和软件层调度；复杂网络仍有算子边界 | 推荐，先小规模正确，再增加算子 |
| C：完整通用 NPU/GPU 式平台 | 能支持更广泛的算子、精度和执行方式 | 编译器、运行时、访存、缓存、一致性和验证工作量大 | 十天内不作为交付承诺 |

成熟开源 NPU 可以提供架构参考，但其现成 RTL、工具链和总线移植并不自动比小规模自主实现省时。
参考：NVDLA 的 host 配置接口和独立数据主接口组织，https://nvdla.org/hw/v1/integration_guide.html 。本方案不计划在十天内移植完整 NVDLA。

## 5. 解决 RAM/ROM 容量担忧

| 内容 | 存放位置 | CPU 是否需要一次装下全部内容 |
| --- | --- | --- |
| RISC-V 驱动、装载协议、调度、简化后处理代码 | ROM | 是，必须检查链接后的 .text 大小 |
| CPU 栈、状态、少量任务、收发小块 | CPU RAM | 只需有限容量 |
| 模型权重、偏置、量化常量 | DDR | 不需要 |
| 网络任务表 | DDR | 每次取一条或几条 |
| 原图、中间特征图、检测头输出 | DDR | 不需要 |
| 当前输入/权重 tile、部分和、输出块 | 加速器片上缓存 | 只保留当前工作集 |

示例：每条描述符 64 字节，100 条只占 6400 字节；即使任务表更大，也可以从 DDR 分批读取。增加模型层数不应变成在 CPU 程序中增加数百段专用推理代码。
CPU 调度结构是“取描述符 → 配置 → 启动 → 等待 → 下一条”。

当前 link.ld 把 .rodata/.data 放在 64 KiB RAM，所以把大数组写成 const 并不能解决容量问题。模型必须作为外部二进制数据装入 DDR，不编译成 CPU 数组。
不在 CPU 上部署 PyTorch、Python 或通用模型解析框架。PC 负责离线模型处理，CPU 只读取简单二进制描述符。

32 KiB ROM 对小裸机调度程序有可行空间，但在完整驱动、后处理编译前不能保证装得下。
每次以 ELF/map 检查 ROM 与 RAM；先减少大型 printf、浮点、通用库和非必要功能。CoreMark 与 AI 固件可以分开构建。
确有需要时再扩大 ROM，并同步调整 ROM 地址位宽和链接脚本，而不是先让 CPU 从 DDR 取指。

DDR 虽然较大，仍需要片上工作缓存提供计算带宽；这些缓存不与 CPU 的 64 KiB RAM 抢同一个地址区。综合后统一核对整个 FPGA 的 DRM/APM/LUT 资源。
按用户所述 512 MB 规划；当前 DDR 模型的默认几何也对应 x16、28 位原生地址空间。最终以实板芯片与已验证 IP 配置为准。

## 6. CPU 访问 DDR 的三个层次

| 方式 | 行为 | 代价 | 建议 |
| --- | --- | --- | --- |
| MMIO 分块窗口 | CPU 配置地址和长度，启动搬运，轮询完成，再从窗口读写小块 | 需要 staging 缓冲与搬运状态；CPU 不能直接解引用任意 DDR 指针 | 十天主方案 |
| 普通 load/store 地址窗口 | CPU 对映射地址执行普通访存，由总线等待 DDR | 当前 dev_* 没有 ready，需要补可变延迟握手和流水线保持/完成逻辑 | 后续演进 |
| CPU 程序/数据全面放 DDR | DDR 支持常规堆栈、取指与数据访存 | 还涉及启动、性能、Cache 和更多验证 | 当前不做 |

MMIO 分块窗口仍然满足“CPU 能访问 DDR”，但访问是显式操作，不是普通指针。
建议一次 256 字节：CPU 填充窗口，提交 DDR 写命令，等 DONE；读时提交命令，等 DONE 后读窗口。
数据窗口中的寄存器/RAM按现有固定同步读时序响应，DDR 的不确定延迟由外设内部承担。
第一版只需一个在途搬运命令；不要丢弃窗口忙时的写入，应由 ready/status、错误状态和软件流程明确控制。

参数传输可以如下进行：

```text
外部文件 → SPI 接收 FIFO → CPU 分块取数据
    → 256B DDR 访问窗口 → 顺序搬运控制器 → DDR
```

CPU RAM只需很小的暂存，或者逐个 32 位字转发；不需要先把几 MB 权重完整放进 RAM。
后续可以让 SPI 接收缓冲直接启动 DMA，减少 CPU 搬运，但不作为第一版条件。

## 7. 所谓“调度器”要区分三件事

1. 模型调度：CPU 按拓扑顺序提交各层任务。
2. 地址分配：PC 工具提前确定权重与特征图位置，以及何时可复用；第一版不做动态显存分配器。
3. DDR 端口分配：CPU 搬运端和计算引擎使用同一 DDR 控制器。

CPU 访问同一颗 DDR，本来就需要定义端口使用规则；这不意味着必须把 CPU 的普通内存也迁入 DDR。
第一版使用阶段互斥，保留 CPU 独立 ROM/RAM：

```text
LOAD：CPU 装载模型、图像、任务表，计算引擎不访问 DDR
FETCH：CPU 取下一条任务，配置计算引擎
RUN：计算引擎使用 DDR；CPU 继续从 ROM/RAM 执行并轮询 MMIO
RESULT：在途访问全部完成后，CPU 读取结果或下一条任务
```

DDR owner 只在命令队列、读返回和写数据全部排空后切换；不能在一个 burst 中途切换。
CPU 控制寄存器访问不受 DDR owner 阻塞。多个访问源先汇合到一份顺序搬运接口，不需要一开始做完整多主 AXI 互联。
优点是简单且容易检查正确性；缺点是 CPU 装载、推理和结果读取不能全部重叠，吞吐不是最佳。
推理期间可以接收少量外部消息，但大文件发送方必须遵守流控，不能无限写满 SPI FIFO。

你的已验证顺序 DDR 读写工程非常适合这种方式：补可配置起始地址和长度，在块之间跳转，块内仍然顺序传输。
现已核对该工程：85 个 IP 端口、7 个参数与行为模型一致；原读写控制器在功能级 FIFO 替身下完成三种延迟/停顿配置的读回测试。视频地址步距和帧槽协议不能原样用作 AI 连续显存接口，详见 DDR 核对报告。

## 8. 最小引擎范围和模型策略

第一轮至少实现可配置的 CONV2D：K=1/3、stride=1/2、padding=0/1、多输入/输出通道、偏置、明确的移位量化、ReLU/旁路。
增加 COPY 作为特征图布局整理；是否加入池化、ADD、上采样和 SiLU，由首个已经软件复现的模型决定，不先承诺所有 YOLO 均可运行。
先单缓冲、低并行度，之后再增加 ping-pong 和阵列规模。

数值格式在选定已有验证资产后冻结。若使用 CNN_FPGA 的 MAT，必须保留至少 9 位有效权重和它的舍入规则；可用 16 位容器保存权重，避免截断或临时重训。
16 位激活可容纳该工程的非负 8 位中间结果及有符号检测输出，但仍需按每层规则钳位，不能省略它原有的量化。
16 位存储的代价是权重/激活流量增加；十天内先接受这些成本，资源/带宽优化后置。

先选择“有可复现量化权重、样例输入、逐层黄金输出和清楚后处理定义”的小检测网络。
优先审查 CNN_FPGA 的已有资产；它是专用小网络，不将其当成标准 YOLOv5/11/26 权重处理。其完整检测输出还需软件核对，不能仅凭单层 MAT 存在就承诺检测正确。
若这些资产无法尽快复现，应在前两天换到更可靠的现成模型，避免直到硬件完成才发现缺少可验证模型。

YOLOv5n 保留为学习和算子扩展候选；原版还需要 6×6 首层、SiLU、残差、上采样、SPPF和拼接。
YOLO11/26 的注意力等扩展暂不进入最小交付。更新网络不应打断 DDR、MAC、配置和装载这些可复用基础模块。

## 9. SPI 与 ARM 的边界

SPI 实现由他人负责，本任务先用 testbench/仿真装载端代替。预留按块收发和状态接口即可。
应约定字节序、块长、目标 DDR 偏移、长度、序号、CRC、接收可用空间、完成/错误状态和复位行为。
接入 CPU 时用固定同步读的状态/数据寄存器；SPI 与 CPU 的异步跨域由接口明确承担。

若 ARM 为 SPI 主机、FPGA 为从机，FPGA 待发送消息进入 TX FIFO，由 ARM 轮询并提供时钟读取；不假设 FPGA 从机会自行产生传输时钟，也不强制新增中断线。
ARM 可以做文件存储、字节传输和消息转发；推理、检测头解码、阈值筛选与 NMS仍应在自研系统完成，才有清晰的计算归属。

本地赛题指南要求“基于设计的 RISC-V 处理器”构建 AI 单元，并提到融合传感器/显示设备；仅依据该指南，无法保证 ARM 作为通信桥的最终合规认定。
保持上位机协议独立于 ARM，让外部下载器可替换；展示时明确 ARM 的实际职责。完整规则与组委会解释仍需按参赛要求核对。

## 10. 十天工作顺序与检查点

下表以用户已有 CPU/UART 上板和可复用顺序 DDR 工程为前提，是工程安排，不是完成时间保证。

| 时间 | 本任务重点 | 检查点 |
| --- | --- | --- |
| D1 | 审阅真实 DDR 工程；统一行为模型/实 IP 接口；选择可验证模型资产 | 明确地址、时钟、初始化和突发语义；软件样例有可信输出 |
| D2 | CPU DDR 分块访问窗口与 owner 切换 | CPU 写入、读回、CRC，高地址与块边界通过仿真及上板 |
| D3 | MAC、量化、输入/权重/部分和缓存 | 符号、边界、空泡、通道补齐、舍入匹配整数参考 |
| D4–D5 | 可配置卷积，DDR 读入/计算/写回 | 不同尺寸、通道和 1×1/3×3 卷积逐项一致；尽早上板 |
| D6 | CPU 任务循环，两份不同配置的小网络 | 同 RTL/位流运行，不靠重新综合换模型；各自输出正确 |
| D7 | 首个完整小检测模型的必要算子与后处理 | 全网逐层和最终检测输出对拍 |
| D8 | 接入他人 SPI 模块、外部加载模型与图像，完成静态图检测 | CPU 和引擎独立完成计算，ARM 只转发，实际框可检查 |
| D9 | 综合、时序、板级稳定性、周期测量和缺陷修复 | 稳定位流/固件/模型资产备份，确定可展示范围 |
| D10 | 重复演示、文档与证据整理 | 不再加入大架构功能 |

SPI 可以独立推进，但自己的 S1..S5 验证不等待 SPI 就绪。
每个主要里程碑都应有上板检查，不把所有实板验证拖到最后一天。

若 D4–D5 仍无法完成可靠的单层 DDR 闭环，完整检测交付风险将很高；应停止增加并行度、复杂算子与实时视频，优先修复存储和计算正确性，并明确报告距离完整检测的缺口。
若 SPI 未按时就绪，保留仿真装载与其他既有调试路径作为证据，但不能将其等同于完整外部加载演示。
若显示/摄像头接口尚未验证，先完成静态图的结果正确性，再评估参考工程的 overlay/显示链；视频同帧与显示要求不能用神经网络单元测试代替。

## 11. 建议交付与后续演进

建议十天交付范围：CPU 可调度、模型数据在 DDR、CPU 可分块访问 DDR、至少一份实际可验证的小模型、同硬件运行另一份不同配置的网络、具备外部加载接口及可解释结果。
完整检测是正式目标；如果只能完成算子或小网络加速，要据实描述，不能声称已完成任意 YOLO 或通用 AI 部署。

后续顺序：扩大算子集合 → 更好的离线模型编译 → 双缓冲与访存重叠 → 并发仲裁 → CPU 普通 DDR 访存 → 按测量结果增加缓存/并行度。
复杂 Cache 和统一内存系统不作为小裸机驱动容量不足的第一解决方法。
