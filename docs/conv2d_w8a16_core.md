# W8A16 卷积计算块与参考 C 对拍

日期：2026-10-26。状态：计算块行为仿真和 lint 通过，其MAC/量化组件已接入可选W8A16 DDR与CPU路径；任务表和完整检测网络尚未完成。

## 1. 当前目标和实现边界

先完成参考模型的数值语义及可综合的数据通路，再接 DDR 和 CPU 调度、补齐所需算子、综合并上板。
暂不增加并行规模、层间融合或脉动阵列；根据实际资源、时序和运行结果决定优化。
后续若准备实现脉动阵列，先停止该项代码修改，向用户解释数据、权重、部分和如何在阵列中移动。

新计算块只处理一个输出像素、最多四个输出通道，输入通道分为若干个 16 通道块。
输入为有符号 INT16，权重为有符号 INT8；每个 MAC 发射拍仍计算 4×2=8 项乘积。
没有扩大乘法器数量；16×8 位乘法和 Q13 量化会增加资源，实际 APM、LUT、RAM 和频率待 PDS 检查。
没有把不同网络层铺成多套物理卷积电路。

## 2. 模块划分

```text
未来的 DDR/片上供数控制器
    → load_valid/ready：按 tap 装载输入与四个权重银行
    → block_valid/ready：提交一个 16 输入通道块
    → conv_mac_tile(ACT_WIDTH=16)：缓存同步读、四路双乘积、INT64 部分和
    → conv2d_w8a16_core：跨块累加，保留两组尺度对应的部分和
    → requant_q13：分组缩放、Q13 偏置、钳位、ReLU、INT16 重定标
    → out_valid/ready：一个像素的四个输出通道
```

- `vsrc/conv_mac_tile.v`：增加综合参数 `ACT_WIDTH=8/16`。默认 8 保留旧接口；输入缓存字宽为 `16*ACT_WIDTH`，权重银行仍为 128 位。
- `vsrc/multiply_adder_w8a16.v`：固定 16×8、25 位求和输出、3 级同步复位的厂商 IP 替换边界。
- `vsrc/requant_q13.v`：一个标量量化单元，四个通道分时使用；与已有 `requant_int8` 分开，避免改变原 W8A8 的舍入 ABI。
- `vsrc/conv2d_w8a16_core.v`：块级控制与上述组件的集成。

`ACT_WIDTH` 是综合参数。一个 `conv_mac_tile` 实例只生成一个位宽的分支；不会因此自动生成两套 MAC。
独立core不直接例化进SoC；DDR引擎复用其中的MAC/量化组件并维护四像素部分和。SoC默认仍为W8A8，可用`AI_ACT_WIDTH=16`选择新路径，见 [DDR与CPU接口](conv2d_w8a16_ddr.md)。
上板新路径时，应在顶层配置中选择计算实现；不要为了保留源文件而同时实例化两套独立引擎。

## 3. 数值规则

对每个输出通道：

```text
acc[g] = 该尺度组所有输入通道、所有 kernel tap 的 Σ(INT16 × INT8)
rhu(a,s) = s==0 ? a : arithmetic_shift_right(a + 2^(s-1), s)
q13 = rhu(acc[0] * multM[0], shiftM[0])
    + (启用组1 ? rhu(acc[1] * multM[1], shiftM[1]) : 0)
    + bias_q13
v13 = clamp(q13, INT32_MIN, INT32_MAX)
v13 = relu ? max(v13,0) : v13
output = clamp(rhu(v13 * multY, shiftY), -32767,32767)
```

每个尺度组的全部输入块必须累加完成后才舍入，不能在每个 16 通道块结束时量化。
两组先分别舍入再相加；这与先相加再缩放可能相差一个或多个整数码。
例如 RHU(+0.5)=1、RHU(-0.5)=0；不同于旧 INT8 路径负半整数远离零的规则。
`out_clamped` 标记 Q13 超出 INT32 的钳位，不表示指令执行失败；输出 INT16 饱和也不是错误。
检测头末级可关闭 ReLU，保留负输出。

量化乘数范围为 0..2^31−1、右移为 0..95，不支持负移位。
实际参考资产的 shiftM 为 27..41，shiftY 为 20..29，位于支持范围内。
量化单元用 96 位有符号中间乘积，避免 INT64×INT32 过早截断。

两组是输入张量量化尺度的分组，例如拼接来自两条支路的特征图；不是 depthwise/group convolution。
每个输出通道仍连接两组的全部有效输入通道。

## 4. 外部接口和调用顺序

| 接口 | 约定 |
| --- | --- |
| `start_valid/start_ready` | 接收一次输出像素任务，并锁存全部 cfg；忙时不接受新任务 |
| `cfg_taps` | 1 或 9，对应 1×1 或 3×3；tap 顺序为 KY 后 KX |
| `cfg_blocks0/1` | 两组各有多少个 16 通道块，组0至少1块，组1为0表示关闭 |
| `cfg_lane_mask` | 标记四路中的有效输出通道，至少一位为1；无效通道最终写零 |
| `cfg_mult_m0/1`、`cfg_bias_q13`、`cfg_mult_y` | 每路32位，lane0在最低位；multY虽在原模型中为每层共享，这里允许每路配置 |
| `cfg_shift_m0/1`、`cfg_shift_y`、`cfg_relu` | 全部在任务开始时锁存 |
| `load_valid/load_ready` | 在装载状态下逐字写入缓存；`load_tap` 必须小于9 |
| `load_weight=0` | `load_data` 为16个INT16，低位为第0个输入通道 |
| `load_weight=1` | `load_lane` 选择0..3；`load_data[127:0]` 为16个INT8权重，高128位忽略 |
| `block_valid/block_ready` | 当前块的输入和四路权重全部装满后才能握手计算；每块都要求重新装载，防止误用陈旧缓存 |
| `compute_enable` | 暂停/推进 MAC 的同步读、IP流水和有效标记；不是整个 core 的全局时钟使能 |
| `out_valid/out_ready` | 64位四路INT16输出，在反压期间保持数据、错误和钳位标志 |
| `issue_valid` | 本拍实际发射8项乘积；可供后续性能计数使用 |

一次任务按以下顺序执行：

1. `start` 握手，配置不必继续保持。
2. 按组0的第0块到最后一块，再按组1的顺序供数。
3. 每块装载 `cfg_taps` 个输入字，以及每个 tap 对应的四个权重字。
4. `block` 握手后计算，完成后回到装载状态；供数端可以暂停等待。
5. 最后一块完成后自动对四路结果量化，等待输出握手。

未装满缓存时 `block_ready=0`，不会静默复用前一个块；供数端必须完成装载后再提交。
供数端负责根据 stride、padding、空间坐标取数，以及尾输入通道/无效输出通道补零。
core 内没有 DDR 地址发生器，不把片上缓存接口冒充内存搬运。

## 5. 验证结果与范围

```bash
make test-conv2d-w8a16
python3 scripts/test_conv_mac_tile.py
```

期望值来自材料中的原始 `conv_layer`，输入/参数打包程序在 `pc_ai/w8a16_vectors.c`。
测试运行器 `pc_ai/verify_w8a16_rtl.py` 只使用 Python 标准库，不实现 Python 数学网络。
结果在 `pc_ai/outputs/w8a16_rtl/`。

- 72份真实卷积记录、12种补充配置，每种选3个空间位置，共252个输出块；使用独立5×7张量，不连续执行网络。
- 覆盖1×1/3×3、输入通道跨16、两组独立尺度、输出不足4通道、ReLU开关、Q13钳位；stride1/2及padding由C供数端提取并补零patch，尚未验证RTL地址生成。
- 加上2次复位重放，共254个卷积输出块、1016个输出槽位，包含无效槽位补零。
- 634个量化向量由C `__int128` 计算，覆盖INT64极值、96位乘积、0..95右移边界、负半整数、INT32钳位、INT16饱和、非法量化参数；3次复位重放后共637次输出检查。
- 检查配置锁存、MAC流水暂停、输出反压、每块缓存新鲜度、3种非法任务配置、在途计算及结果反压时复位。
- 新量化单元和计算块通过严格Verilator lint；原默认W8A8 MAC的21个用例通过，现有DDR引擎lint通过。

这不是完整检测网络仿真，不是72层串联验收，不是独立软件全网复核，也不是PDS或真实乘法IP对拍。
第三方权重与材料保持只读；未重新训练、未跑CoreMark。

## 6. 后续连接和加速接口

已给现有DDR控制路径增加32字节INT16输入装载、两组部分和及INT16写回，并验证CPU连续两层；任务表扩展待下一阶段。
继续保留分开的供数、MAC、量化和结果握手；CPU仍只提交层任务，不参与逐乘法供数。
DDR集成应继续利用现有4相邻像素的权重复用调度，不为每个乘法发起DDR请求。
当前core是数值与接口验收块；DDR控制器可以复用其中的MAC和量化组件，并维护多个像素的部分和上下文。

暂不做跨层融合。当前按输出通道分组的生成顺序，与下一层3×3卷积所需的完整通道和相邻行不完全一致。
后续融合需要安排输出顺序、行/分块缓存和分支结果保留；不能直接连接两层valid信号就认为省掉DDR。

若将来换成脉动阵列，应在供数缓存与MAC之间增加适配层，继续输出约定的部分和，并沿用量化和层任务语义。
当前接口提供这种分工，不承诺任意阵列可在不增加缓冲或改变内部调度的情况下直接插入。
性能优化以综合和上板测量为依据，准备实施脉动阵列前先解释其数据组织。
