# W8A16 DDR与CPU调度闭环

日期：2026-10-26。状态：DDR行为模型、RV32I连续两层、错误处理及跨时钟仿真通过；尚未PDS综合、真实IP对拍和上板。

## 1. 实现方式

```text
CPU时钟域：读DDR描述符 → 配置MMIO → START → 轮询 → 窗口读回
                   │ 稳定邮箱与请求/应答翻转握手
DDR用户时钟域：conv2d_ddr_engine(ACT_WIDTH=16)
   → ddr_chunk_client / ddr_block_transfer → DDR IP用户接口
   → 16通道输入缓存、四个权重银行
   → 4×2 W8A16 MAC → 两组部分和 → Q13量化 → INT16 DDR输出
```

扩展现有 `conv2d_ddr_engine`，综合参数 `ACT_WIDTH=8/16`；没有复制并同时例化两个完整引擎。
`soc`、`peripheral_bus`、`ddr_cpu_window` 通过 `AI_ACT_WIDTH` 传递选择，默认8，保留原W8A8行为。
启用新路径示例：`soc #(.ENABLE_DDR(1), .ENABLE_AI(1), .AI_ACT_WIDTH(16), .CLK_FREQ(实际CPU频率))`。
这些参数不生成CPU或DDR时钟，实际PLL和DDR IP由板级顶层连接。

DDR引擎复用已验证的 `conv_mac_tile(ACT_WIDTH=16)` 和 `requant_q13`，保留原4相邻输出像素调度。
四个像素复用同一批权重，各有两组INT64部分和上下文；不为每个乘法发DDR请求。
独立的 `conv2d_w8a16_core` 仍用来验收一个像素的完整计算，它没有与DDR引擎同时铺成另一套MAC。
本阶段没有层间融合、双缓冲或脉动阵列，也没有扩大4×2乘积并行规模。

## 2. CPU寄存器

原输入、权重、偏置、输出、尺寸、卷积及状态寄存器地址不变，新增/扩展：

| 地址 | 寄存器 | 内容 |
| --- | --- | --- |
| 0x30238 | AI_POST | W8A16只接受4=INT16/Q13，6=INT16/Q13+ReLU；旧W8A8仍只接受0/1/3 |
| 0x3023c | AI_QUANT | W8A16逐输出通道32字节量化表基地址，16字节对齐 |
| 0x30240 | AI_GROUP | 0=单尺度；否则为第二组起始输入通道，须16对齐且小于Cin |
| 0x30244 | AI_FORMAT | 只读8或16，表示综合时选择的激活位宽 |
| 0x30248 | AI_OPCODE | 复位1=卷积；2=INT16 ADD；3=通道Concat；4=MaxPool5；5=Upsample2x |

W8A16不接受旧的POST模式，也不提供未经量化的原始INT64输出模式；错误码7用于数值格式/分组配置错误。
W8A8忽略AI_GROUP；W8A16的输入、输出都为INT16。不能在同一个固定实例中逐层切换8/16位。
AI_GROUP与其余配置一起在CPU忙时冻结，通过同一稳定邮箱跨域，不能对它的各位单独打两拍。
AI_FORMAT为综合常量，写入忽略；软件可在提交前确认格式。

原尺寸、对齐、范围、重叠、DDR原生错误及状态恢复规则保留。
输出不得覆盖输入、权重、启用的偏置及量化表。错误清除不会解除DDR原生FAULT，后者需要共同复位。
参数表逐4通道组加载；后续组参数错误可能发生在前面组已写出之后，不回滚部分结果。

## 3. DDR布局和数值格式

全部地址是DDR字节偏移，不是CPU普通内存指针。

| 张量 | 物理排列及分配 |
| --- | --- |
| 输入 | H-W-align16(Cin)，每元素2字节、有符号INT16 |
| 权重 | align4(Cout)-KY-KX-align16(Cin)，每元素1字节、有符号INT8 |
| 偏置 | align4(Cout)，每元素4字节，有符号Q13；禁用偏置时不读 |
| 输出 | Hout-Wout-align16(Cout)，每元素2字节、有符号INT16 |
| 量化 | align4(Cout)条，每条32字节；无效输出通道不读取 |

量化表每条小端：

| 字节 | 内容 |
| --- | --- |
| 0..3 / 4..7 | u32 multM0 / shiftM0 |
| 8..11 / 12..15 | u32 multM1 / shiftM1；单尺度时忽略，建议填零 |
| 16..19 / 20..23 | u32 multY / shiftY |
| 24..31 | 保留，必须为零 |

乘数限0..2^31−1、右移0..95；两组各自累加完全部输入通道块后再舍入到Q13。
随后相加、加Q13偏置、钳位INT32、可选ReLU、输出重定标并饱和到[-32767,32767]。
具体数学语义见 [计算块说明](conv2d_w8a16_core.md)。

一次输入块读32字节，权重读16字节，量化记录读32字节；底层搬运器处理跨2KiB边界。
每次产生四通道、8字节INT16结果。每个8通道DDR字的第一组从零开始写，第二组读改写已有字。
如果align16(Cout)的尾部还有一个未被覆盖的DDR字，额外写全零，保证全部填充区确定。
输出区无需预先清零；DONE之前仍是部分结果。下一层直接使用该HWC输出，不需要CPU重排。

## 4. 时钟与上板条件

- CPU外设寄存器运行在CPU `clk`；搬运器、卷积、MAC和量化运行在真实DDR IP输出的 `core_clk`。
- `core_clk` 是DDR用户接口时钟，不等于DDR物理CK，也不能用DDR数据速率代替它来设约束。
- 两个时钟不要求相同或整数倍关系；请求/应答用两级同步的翻转握手，多位配置和结果保持稳定后采样。
- 行为模型默认用户周期7.619ns，约131.25MHz，已有CPU25/50MHz测试不是DDR25/50MHz测试。
- 复位须协调CPU窗口、DDR控制与DDR IP，异步拉低、各逻辑域同步释放。
- 实板需要真实时钟约束、同步器标记及邮箱最大延迟约束；不能仅凭RTL握手或将全部跨域路径设false path认为已完成CDC物理检查。

提高CPU频率需同步更新实际时钟源、约束和`CLK_FREQ`，后者主要用于UART分频，不改变计算协议。
`DDR_TIMEOUT_CYCLES` 单位为DDR用户时钟周期，4096周期在200MHz下为20.48微秒；按实际允许的连续无进展时间配置。
CPU窗口测试的软件轮询次数上限也与CPU频率相关；完整卷积等待不使用短块超时。
当前仿真没有证明任何组合是目标器件的实际最高频率，MAC/量化路径能否跑到真实core_clk须综合、布局布线后确认。

## 5. 测试与结果

```bash
make test-conv2d-w8a16-ddr
python3 pc_ai/verify_w8a16_ddr.py --profiles all
python3 pc_ai/verify_w8a16_ddr.py --prepare-only
```

测试向量由 `pc_ai/w8a16_ddr_vectors.c` 调用原始C `conv_layer` 生成；Python仅打包启动和整理日志。
没有运行完整检测网络，也没有重新实现独立Python网络。

- 12种独立层配置：8种采用真实卷积记录的输出通道子集，4种补充配置；逐原生写拍、DDR最终结果、只读区和边界哨兵核对。
- 覆盖1×1/3×3、stride1/2、padding、Cin跨16、Cout跨4/8/16/32、两尺度分组、ReLU开关、禁用偏置时忽略无效偏置地址、无效通道补零、跨2KiB。
- 每个时序配置检查128个DDR结果字，含两次复位后重放；正常、随机停顿、零读写延迟都通过。
- 10种基础非法配置、14种W8A16格式/分组/参数错误；乘加/量化中共同复位，原生超时FAULT与复位恢复。
- 真实RV32I程序从DDR读取两条描述符，依次执行原模型的model.0和model.1，保留完整32/64输出通道。
- 第一层输入5×7×3，输出3×4×32；第二层直接读取该输出，产生2×2×64。CPU读回及测试台检查两层合计80个128位输出字。
- 固件指令区976字节；资产由外部测试加载端预装DDR，没有将权重编译到CPU ROM。
- CPU25/约131.25MHz DDR、CPU50/约131.25MHz DDR并随机停顿通过；CPU约71.43MHz/DDR约166.67MHz并随机停顿、CPU约166.67MHz/DDR80MHz并零读写延迟也通过。
- 另以`--grouped-cpu`验证第二层为两尺度的补充配置，CPU写AI_GROUP=16，忙时改写被忽略，DDR侧两组计算与C一致；这不是原网络第二层的等价替换。
- W8A8量化DDR的16种配置、原CPU原始模式和INT8两层程序的受影响检查通过；未运行CoreMark。
- 8/16位DDR窗口配置均通过严格Verilator lint。

输出在 `pc_ai/outputs/w8a16_ddr/`，`result.json`为普通/全配置报告，`clocks_result.json`为额外时钟检查。
