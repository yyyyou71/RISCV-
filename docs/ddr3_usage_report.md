# DDR3 行为模型与 ziguang-fpga2 原工程核对报告

日期：2026-10-24。范围：源代码、接口和定向事务仿真。本轮未运行 PDS、原厂 PHY 联合仿真或实板测试。

## 1. 结论

`vsrc/ddr3.sv` 可以继续作为该配置 DDR IP 的用户接口事务仿真基础。
本轮比较原工程 `ipcore/ddr3/ddr3.v`，85 个端口的名称、方向、参数化位宽，以及 7 个参数的名称与默认值全部相同。
接口声明相同不代表原厂内部全部行为、时延和 PHY 已被复现。

原工程最适合复用的是原厂 IP 配置、板级引脚与时钟约束、写前缓存完整突发、读前预留 FIFO 空间及读写握手机制。
AI 搬运应增加显式地址/长度/开始/完成接口，不直接沿用视频 SOF、帧槽和整帧完成协议。

## 2. 原工程的数据路径

主工程为 `../../materials/ziguang-fpga2/pcie_dma_test.pds`，目标 PG2L100H、FBG484、-6。
顶层 `hdl/pcie_dma_test.v` 实例化 `frame_ring_ddr3`，其数据路径是：

```text
HDMI 像素
 → hdmi_in_detector（整形、帧头标记）
 → fifo_2_ddr（16 位写入 / 128 位读出，跨时钟）
 → ddr3_write_ctrl_lite（预存完整 16 拍突发，再写 DDR）
 → 原厂 ddr3 IP
 → ddr3_read_ctrl（预留接收空间，提交读命令）
 → ddr_2_fifo（128 位跨时钟 FIFO）
 → 后续图像处理 / PCIe 传输
```

主要文件：
- `hdl/new_ring/frame_ring_ddr3.v`：整体连接、IP 例化和视频帧槽状态。
- `hdl/new_ring/ddr3_write_ctrl_lite.v`：完整 burst 缓存、AW/W 控制。
- `hdl/new_ring/ddr3_read_ctrl.v`：AR/R 控制与读 FIFO。
- `ipcore/ddr3/ddr3.v`、`ddr3.idf`：原厂配置和顶层接口。
- `fdc/pcie_dma_test.fdc`：真实板级时钟、PHY 固定位置与引脚约束。

## 3. 已确认的接口与时钟

默认几何为 ROW=15、COL=10、BANK=3、DQ=16，用户数据拍为 128 位，即 16 字节。
当前几何的 x16 原生地址空间对应 512 MiB；模型稀疏存储的实际已写容量另行限制。
AW/AR 的地址宽度 28 位，len 为 4 位，最多 16 拍。
写侧没有输入 WVALID/WLAST 或标准 AXI B 响应，读侧没有 RREADY。

写数据必须在 WREADY 采样沿之前准备好；原工程使用 `word_reg` 预取，遇到停顿保持数据。
读命令发出前保证整个 burst 的空间；之后每个 RVALID 都必须接收。
新搬运模块应据实际接受的 beat 和 WUSERO_LAST/RLAST 检查完成，不依赖固定时延。

FDC 以 sys_clk=25 MHz 为 DDR 参考时钟，给 DDR 用户时钟设置 84/16 倍频关系，即 131.25 MHz。
模型默认 7.619 ns 的 core_clk 周期与该名义频率对应；这是行为时钟设置，不是本轮时序收敛结果。
CPU/计算域与 DDR 域应通过 FIFO 或可靠握手跨域。

若把 DDR 子系统移到新 SoC，FDC 中的 `u_hdmi_fifo.u_ddr3...` 路径必须跟随新的实例层级更新。
不能把包含 PCIe/视频时钟对象的整份约束直接原样加入 CPU 工程。

## 4. 重要发现：字节地址与原生地址

原厂自带 `example_design/rtl/test_wr_ctrl_v1_0.v`：
- 初始化写入采用 len=15，即每次 16 拍。
- 相邻这类命令地址递增 128。
- 数据拍对应的原生地址每次递增 8。

`test_rd_ctrl_v1_0.v` 也在每个 RVALID 将原生地址递增 8。
这与当前模型的原生地址步进一致。

对当前 x16 配置：

```text
一个数据拍 = 128 bit = 16 字节 = 8 个 x16 存储位置
16 拍突发 = 256 字节 = 128 个原生地址单位

原生地址 = 线性字节地址 / 2     （转换前检查对齐和范围）
```

而当前视频工程的读写控制器将命令地址递增 256；按模型与上述原厂例程语义，会在两个突发之间留出一段空隙。
读写两侧采用相同公式，所以仍能逐块读回正确内容，不能仅凭回读成功推断命令地址以字节计数。
本轮仿真复现：首突发数据位于原生 0x000..0x078，次突发从 0x100 开始，0x080 对应块仍未写入。
这不是新搬运模块应采用的紧密连续布局；本轮没有修改原视频工程。

对 AI 系统应采用：上层统一字节偏移，底层适配器转换原生地址。
另需遵守模型的列内回绕：COL=10 时一次突发只能在当前列范围内递增，跨列必须拆成新命令；默认对应 2048 字节边界。
不能直接把 TridentVision 的 256 位字地址也接到这里。

## 5. 哪些视频逻辑不能直接当成通用 DMA

- `MAGIC_SOF=16'h0001` 是视频数据中的帧头标记。任意权重/特征数据也可能等于该值，不能用它控制 AI 地址。
- 写侧通过遇到下一帧 SOF 标记上一帧完成；单次模型块传输可能永远没有“下一帧”。AI 应按明确长度和实际写完成判定。
- 读侧自动选择已完成帧槽、读取整帧；AI 需要 CPU 指定地址与长度。
- 顶层保留的部分 dma_start/clr 等端口实际上未使用，不能只给这些端口接 CPU 启动信号就认为完成控制接入。
- 读控制器默认 FIFO 深度参数为 64，而生成的 `ddr_2_fifo` 配置为 256、计数端口也更宽。当前读取限制较保守，但复用时应统一容量与位宽，不沿用不一致常量。

## 6. 本轮验证

脚本：`build/ai_reference/ziguang_ddr/check_reference.py`。

1. 静态比较两个 DDR 顶层接口：85 端口、7 参数一致。
2. 原样读取原工程 `ddr3_write_ctrl_lite.v` 和 `ddr3_read_ctrl.v`，与本工程 `ddr3.sv` 联合仿真。
3. 用功能级 FIFO 替身模拟控制器所依赖的预取/同步读取行为；这不验证真实 FIFO IP 的 CDC。
4. 缩小帧为每帧两个 burst，共 32 个 128 位数据拍；再输入下一帧 SOF burst，以触发原工程的帧提交。
5. 核对写命令地址、读命令地址、突发长度及全部 32 拍数据，并检查原生地址空隙。

结果：

| 配置 | 结果 |
| --- | --- |
| 模型默认读写延迟 | PASS，32 拍数据一致 |
| 零读写延迟 | PASS，32 拍数据一致 |
| 读延迟 11、写延迟 7、周期与随机停顿 | PASS，32 拍数据一致 |

日志与机器可读结果：
- `interface_comparison.json`
- `normal.log`、`zero_latency.log`、`stalled.log`
- `results.json`

均在 `build/ai_reference/ziguang_ddr/`。
这验证了这些配置下“原控制器 + 行为模型”的读回一致性，不证明行为模型与原厂控制器的所有时序和行为一致。
本轮未跑 1080p 整帧、五帧环满载、原厂 PHY/存储芯片联合仿真或实板带宽测试。

## 7. 行为模型的使用边界

模型支持初始化、延迟/随机停顿、读写命令队列、读写掩码/ID、稀疏存储、部分 APB 功能等用户事务行为。
Pin-level DDR 保持空闲，PHY 校准/debug 控制不模拟；真实刷新、bank 调度和板级时序不构成其性能模型。
复位中断在途任务，但不清空存储；未写地址默认返回 X，用于暴露提前读。

默认 `DDR3_MODEL_SLOTS=65536`，x16 时每槽 16 字节，仅能保存约 1 MiB 已写数据。
地址空间覆盖范围与已写存储容量必须区分；超过表容量会主动报错，不会把高地址静默映射回低地址。
完整网络仿真应按数据量增加该宏，并根据模型报告核对总占用。

原工程和本工程声明了同名 `ddr3` 模块，仿真源列表只能选择行为模型或原厂 IP 之一，不能同时加入。

## 8. 对当前 AI 方案的调整

保留已经上板的原厂 IP 配置、物理引脚和正确的时钟关系。
新建命令式搬运层，接口采用“起始字节地址、长度、读/写、开始、忙、完成、错误”，内部复用完整 burst 预缓存和接收空间预留方法。
去除 SOF/帧槽依赖，显式转换地址并拆跨列请求。
先接 CPU 的小块 DDR 访问窗口，再让计算引擎使用同一命令式搬运层。
这比把整个视频环形缓冲当成 AI 显存接口，更符合可更换模型的目标。
