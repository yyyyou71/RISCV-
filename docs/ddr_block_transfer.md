# DDR 指定地址、指定长度块搬运模块

文件：`vsrc/ddr_block_transfer.v`。所有接口均在 DDR 的 `core_clk` 域。
状态：已完成独立 RTL、行为模型回归和静态检查，尚未接入 CPU MMIO 或进行本模块的实板验证。

## 功能与限制

- 每条命令独立指定字节地址、字节长度、读写方向。
- 支持 16～256 字节，地址和长度均按 16 字节对齐；零长度和超范围请求报错。
- 一次只处理一条命令；没有视频帧头、固定帧槽或自动循环读写。
- 默认匹配紫光 x16 DDR：128 位数据、28 位原生地址、10 位列地址。
- 内部缓存为 16×128 位，共 256 字节，读写共用。
- 自动将跨列边界的块拆成多个原生突发。
- 读写结果、命令完成、参数错误与需要系统复位的总线故障分别定义。

大于 256 字节的数据由上层循环提交多条命令。第一版没有非对齐或部分字节写入功能，原生 WSTRB 对有效传输的每个字节均为 1。

## 上层接口

| 信号 | 说明 |
| --- | --- |
| `cmd_valid` / `cmd_ready` | 两者同拍为 1 时接受命令，锁存全部参数 |
| `cmd_write` | 1=写 DDR，0=读 DDR |
| `cmd_addr[31:0]` | 从 DDR 起点计算的线性字节偏移，不是原生 DDR 地址 |
| `cmd_len[31:0]` | 本条命令的字节数 |
| `wr_valid` / `wr_ready` / `wr_data[127:0]` | 写命令被接受后，按顺序发送恰好 `cmd_len/16` 个数据拍 |
| `rd_valid` / `rd_ready` / `rd_data[127:0]` | 读结果以握手方式输出，允许上层暂停 |
| `rd_last` | 当前有效输出是整条读命令的最后一个数据拍 |
| `busy` | 命令执行中，包括收写数据和等待上层取走读结果；致命故障时也保持为 1 |
| `done` | 本条命令成功完成，粘滞保持 |
| `error` / `error_code[3:0]` | 错误及原因，粘滞保持 |
| `fault` | 总线故障锁定，需要共同复位本模块和 DDR IP |
| `clear_status` | 空闲时清除 done/error/error_code，不清除 fault |

命令或写数据在 VALID=1、READY=0 时应保持不变，直到完成握手。
忙时 cmd_ready=0：一拍命令不会被接受；若想排队等待，提交方保持 VALID 和命令参数直到 READY。
模块内部不额外排队。已接受命令的参数可以不再保持，执行过程使用锁存值。

`wr_data[7:0]` 对应当前拍最低字节地址，采用小端字节排列。
`rd_last` 对应整块结束，不对应内部拆分后的某个原生段结束。

下一条命令被接受时自动清除之前的完成/错误状态。同拍出现 clear_status 和新命令时，以新命令的处理结果为准。

## 写入时序

```text
命令握手
  → 收齐 wr_valid/wr_ready 数据
  → 提交第一段 AW
  → 根据 WREADY 逐拍供数
  → 如需跨列，继续提交下一段 AW
  → 最后一段最后一拍被 DDR 接受，done=1、busy=0
```

必须先收齐整块再发 AW，因为该原生接口没有 WVALID。
数据在 WREADY 采样沿之前已经出现在 WDATA 上；遇到停顿，当前数据和指针保持不变。
同时检查原生 `axi_wusero_id` 和 `axi_wusero_last`，不靠估计固定延迟判断写完。

## 读取时序

```text
命令握手
  → 提交第一段 AR
  → 每个 RVALID 都写入内部缓存
  → 如需跨列，继续提交下一段 AR
  → 全块收齐后拉高 rd_valid
  → 上层取走最后一个数据拍，done=1、busy=0
```

DDR 原生端没有 RREADY，模块因此先缓存整个块，再向上层提供可暂停的数据流。
上层暂停时 rd_valid、rd_data、rd_last 保持稳定。
只有最后一拍被上层接收后，整条读命令才算完成；不能只等待原生 RLAST 就复用输出缓冲。

## 字节地址转换与跨列示例

默认 x16 配置下：

```text
一拍 = 16 字节 = 8 个原生地址单位
原生起始地址 = 字节起始地址 >> 1
```

请求读取字节地址 `0x7f0` 开始的 64 字节，跨越 2048 字节列边界：

| 段 | 字节地址 | 原生地址 | 拍数 | 原生 len |
| --- | --- | --- | --- | --- |
| 1 | 0x7f0 | 0x3f8 | 1 | 0 |
| 2 | 0x800 | 0x400 | 3 | 2 |

上层仍然只提交一条命令、接收四个连续数据拍。
每段拍数取“整块剩余拍数”和“当前列剩余拍数”的较小值，防止原生突发在列内回绕而覆盖错误地址。
地址范围使用扩展到 33 位的 `cmd_addr + cmd_len` 检查，避免 32 位加法回绕。
默认允许区间 `[0, 0x20000000)`，最后一个合法 16 字节块从 `0x1ffffff0` 开始。

## 错误与复位

| error_code | 原因 | 恢复 |
| --- | --- | --- |
| 0 | 无错误 | — |
| 1 | 长度为零或超过 256 | 修改参数后重试，未发 DDR 命令 |
| 2 | 地址或长度不按 16 字节对齐 | 修改参数后重试，未发 DDR 命令 |
| 3 | 地址区间超出 DDR 原生空间 | 修改参数后重试，未发 DDR 命令 |
| 4 | 原生总线长时间没有进展 | fault=1，需共同复位 |
| 5 | 写返回 ID 或末拍标志不匹配 | fault=1，需共同复位 |
| 6 | 读返回 ID 或末拍标志不匹配 | fault=1，需共同复位 |
| 7 | 执行期间 DDR 初始化完成信号撤销 | fault=1，需共同复位 |

`TIMEOUT_CYCLES` 默认 4096，计量的是原生总线连续没有握手或数据返回的 core_clk 周期数。
写数据收集、读结果输出期间的上层暂停不触发这个看门狗。

致命错误时不假装命令完成、不接受下一条命令；尚未握手的 AW/AR 保持有效和参数稳定，直至握手或共同复位。
fault 状态将 WSTRB 置零，避免尚在排空的写命令继续改变存储；已经写入的内容无法回滚。
恢复时共同复位搬运模块和 DDR IP，等待 ddr_init_done 后重新提交命令。仅清状态或仅复位搬运模块不能保证旧 DDR 事务已经排空。
软件应同时检查 error/fault，不能只等待 busy 变零。

该模块要求执行期间独占 DDR 原生请求端口；CPU 与 AI 的使用权切换和时钟跨域由后续上层模块完成。

## 参数与综合

- `AXI_ADDR_WIDTH`：默认 28，最小 5，且不小于 COLUMN_WIDTH，最大 30。
- `COLUMN_WIDTH`：默认 10，最小 4；用于列边界拆分。
- `TIMEOUT_CYCLES`：正整数，看门狗阈值。
- `AXI_ID`：默认 0，原生请求 ID，并检查返回值。

本模块固定为 x16/128 位数据接口，不支持仅改参数就接 x32 DDR。
256 字节内部 RAM 不整体复位；写块填满后才访问 DDR，读块全部有效后才交给上层，避免复位大量存储资源。
