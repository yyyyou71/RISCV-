# 真实YOLO整网任务导出与分段验证

日期：2026-10-27。状态：96×96全网布局、C黄金输出及原始前向连接比较通过；32×32短区间、96×96前两层和完整model.2 C3的RTL测试通过；整网RTL仍待完成。

## 1. 本阶段做了什么

`pc_ai/export_trident_network.c`读取原`rearch_int8.bin`，参照原C的`forward_fixed`展开计算图。
权重、偏置、量化记录直接取自原资产，数值计算仍调用原C五类算子。
参考目录保持只读，没有新增Python全网数学参考，也没有更改CPU或计算RTL。

```text
24个顶层模块（含C3/SPPF/Detect）
  → 99条基础任务
  → 通用pack_ai_model.py生成AIM1版本2包
  → 原4244字节RV32I调度固件逐条执行
```

| 基础算子 | 数量 |
| --- | ---: |
| 卷积 | 72 |
| ADD | 10 |
| Concat | 14 |
| MaxPool5 | 1 |
| Upsample2x | 2 |
| 合计 | 99 |

72条卷积、10条ADD记录都必须恰好使用一次；导出器检查输入通道、分组边界和输出形状。
通用打包器独立推导形状，脚本再核对拓扑顺序、分支地址、全部节点到检测输出的可达性和容量。
`pc_ai/check_ai_descriptors.c`在主机直接调用生产固件的`validate_task`，99条记录全部通过。
主机检查没有执行MMIO；不将它称为99条任务的CPU/RTL运行验收。

`AI_MAX_JOBS=64`限制的是AIR1中的模型运行请求数，模型内部的task_count可为99。
CPU仍一次只取一条64字节记录，不随网络层数分配张量数组。

## 2. 实际96×96 DDR布局

从`0x10000`开始装载模型包，前64KiB仍留给启动请求和报告。
输入/输出统一为HWC-align16(C)的INT16，权重为O-KY-KX-I的INT8。
全部中间结果各自分配并保留，不做生命周期复用。

| 内容 | 字节数 |
| --- | ---: |
| 头和99条任务 | 6,400 |
| 输入图像（含通道填充） | 294,912 |
| 权重（含填充） | 10,186,624 |
| 偏置 | 43,120 |
| 卷积量化记录 | 344,960 |
| ADD量化记录 | 160 |
| 全部输出/中间图 | 2,427,840 |
| 调试哨兵 | 3,168 |
| 合计 | 13,307,184 |

约12.69MiB，远小于512MiB DDR。权重和任务不编译进CPU ROM，固件仍为4244字节、初始化数据段0字节。
实际逻辑MAC总量403,334,784；按现有填充/8项并行规则，任务报告累计MAC issue应为51,495,120。
issue计数不是总周期，DDR等待、装载、量化和其它算子仍有开销，不能据此宣称实板帧率。

## 3. 六张检测头输出

三种尺度分别输出框回归4通道和分类80通道，96输入对应12×12、6×6、3×3。
这六张张量都保留在DDR。模型头的final_output仍只指最后一张分类图，不代表完整检测结果。
另导出`heads.json`，给出六张图的地址、物理长度、形状、stride、s_box、分类换算multL/shiftL及sigmoid LUT。
该清单供后处理读取，不改变AIM1 ABI，也不假装用Concat拼接不同高宽的头图。
资产的80通道结构不等于已验收COCO80类识别能力，现有权重的检测精度仍需独立评估。

目前CPU没有检测解码/排序/画框代码。原C后处理包含大数组和qsort，不能直接搬入64KiB CPU RAM；
后续应先在PC解码原始头图，再考虑DDR分块读取和有界top-k缓存的CPU实现。

## 4. 命令和产物

仓库根目录执行：

```bash
make prepare-ai-network
# 等价：python3 pc_ai/prepare_trident_network.py
```

默认只导出和检查，不执行任何卷积前向。输入是0..255的诊断渐变图，用于数值调试，不评价检测精度。
所有产物位于`pc_ai/outputs/trident_network/`：

- `network0.json`和逐层原始资产：通用打包器输入。
- `graph.json`：实际层名称、每条任务的来源和输出形状。
- `model.bin/model.json`：AIM1模型包及所有输出地址；模型包包括输出毒值和调试哨兵。
- `request.bin`：装载到DDR地址0的64KiB启动区，指向`0x10000`模型头。
- `tasks.csv`：99条任务的可读索引、名称、来源、尺寸、地址与长度。
- `heads.json`、`layout.json`：检测头清单和容量/计算量统计。
- `prepared.json`：本次准备、C黄金覆盖及RTL区间执行状态。

已有图片预处理的CHW INT16 `.npy`可通过`--input 路径`使用，需要现成Conda环境中的NumPy。
也接受小端、未填充HWC INT16 `.bin`，此时只需Python标准库；像素码必须为0..255。
例如可使用此前`pc_ai/outputs/trident_real/photo_009_view/input.npy`。
同一输出目录后续命令须使用相同输入；源码、资产、输入、图和C导出器哈希用于拒绝错配黄金结果。

### 4.1 完整C黄金值：长任务，由用户运行

```bash
python3 pc_ai/prepare_trident_network.py --golden
```

先沿99条任务调用原C算子并导出所有物理HWC输出，再独立调用原始高层`forward_fixed`。
两次执行的72个卷积和10个ADD注册点必须全部逐值相同，才写成功报告。
`golden/layer000.bin`至`layer098.bin`对应各任务输出；`reference_result.json`记录比较覆盖。
`detections.json`只是原C的候选框输出，并非本CPU的后处理结果。
第二次调用仍使用同一套C算子数学实现，验证的是计算图连接，不宣称独立数值实现的整网证明。
脚本逐层打印进度，完整推理不由代理自行启动等待。

用户已完成上述命令；`reference_result.json`确认99份黄金输出生成成功，72个卷积和10个ADD检查点与原始前向逐值一致，Q13钳位计数为0。
随后复核99份输出共2,427,840字节的长度、绑定哈希和填充区清零均通过。输入为默认96×96诊断渐变图；这不评价检测精度，也不等于RTL已通过。

### 4.2 分段RTL：长区间由用户运行

完成黄金值后，先测试真实96×96前两层（现已通过）：

```bash
python3 pc_ai/prepare_trident_network.py --segment 0:2 --run
```

仿真后端现默认Verilator，可显式指定`--simulator verilator`；保留`--simulator iverilog`用于四态定向检查。
前两层及`--segment 2:7 --run`均已通过，后者验证真实24×24的完整model.2 C3。
该C3包含5个卷积、1个残差ADD和1个Concat，比较53,142个DDR字，累计39,193,418个DDR用户时钟周期、7,077,888个MAC issue，主机耗时约18秒。
此区间的输入仍来自任务1的C黄金输出，不能据此将前9条任务合称为连续端到端验证。

下一步直接执行全部99条任务，由用户运行等待：

```bash
python3 pc_ai/prepare_trident_network.py --segment 0:99 --simulator verilator --run
```

完整入口已准备在`segments/000_099/`，复用现有Verilator模型；尚未运行。
本次只预装原始输入、任务、参数和输出毒值；所有中间图及六张检测头必须由RTL产生，再逐字与C黄金值比较。
预计需要数分钟，具体以实际主机耗时为准。若失败，利用日志中的任务编号再缩小区间定位。

`start:count`的索引从0开始，按`tasks.csv`选区间；如`2:7`是完整model.2 C3，`5:1`是其ADD。
区间内部任务直接读取前序任务的DDR输出；区间以外的必要输入从C黄金值预装。
因此分段对拍能定位某块错误，但不能冒充从原图开始的端到端计算。
`--segment 0:99 --run`才执行全部张量任务，解码/筛选/画框仍是独立阶段。

仅准备仿真时去掉`--run`。区间产物位于`segments/起点_数量/`，有固件、稀疏初值、黄金值及仿真入口。
Icarus使用本区间的`test.vvp`；Verilator使用共享缓存中的可执行文件。
每个后端分别保存`fixtures_后端.json`、`result_后端.json`、`run_后端.sh`和`run_后端.log`。
`fixtures.json/result.json`指最近一次准备/运行，`run.sh`指最近准备的后端。
Python加`--run`会写结果JSON；直接`bash run_verilator.sh`只运行并记录`run_verilator.log`。
该入口可额外传入DDR停顿/时钟参数，例如`bash run_verilator.sh +ddr3_random_stalls=1`，或在Python入口使用`--sim-arg=+ddr3_random_stalls=1`。
不设置短墙钟超时；仿真全局超时可配置，默认脚本给出1000秒目标仿真时间，不等于1000秒主机运行时间。

## 6. Verilator加速与验证范围

使用本机Verilator 5.052的`--binary --timing --assert`编译同一套CPU、AI、DDR模型和SV测试台，不用C算子代替RTL。
CPU/DDR独立时钟、DDR停顿、报告计数、写入范围和逐字黄金比较继续有效，默认不开波形。
首次编译使用`--jobs`指定C++编译并行数，默认最多4；这不改变仿真中的硬件并行度。

编译结果存入`pc_ai/outputs/verilator_network_cache/`，源码/选项/工具版本变化时使用新的模型。
ROM/RAM镜像从当前区间目录装载，按整网容量统一配置主机DDR稀疏表，因此切换区间或输入尺寸可以复用同一编译结果。
ccache和临时文件也位于outputs，避免依赖用户目录的写权限。
当前共享模型模拟DDR表2,097,152个128位槽，Verilator报告主机分配约46MB；这不是FPGA片上RAM用量。

Verilator是两态仿真，不能替代Icarus的X传播检查。
本网络入口为两个后端同时启用`DDR3_MODEL_STRICT_READS`：整个DDR字从未写入时，读取立即报错。
初值和网络写回均为完整128位字；严格模式不会把漏装载的字默认为零。其它DDR测试未定义该宏时保留原模型语义。
该检查不追踪部分写入字内的字节有效性，相关四态检查仍使用Icarus。
