# INT16通道拼接Concat

日期：2026-10-26。状态：DDR拼接、CPU任务表和完整C3小特征图对拍通过；尚未PDS综合或上板。

## 1. 做什么

两张特征图的高、宽相同，将每个像素的通道按A后B的顺序接起来。
例如A为H×W×5、B为H×W×17，输出为H×W×22。
它不做加法、不修改整数码，也不做量化。

```text
同一像素的A通道：[A0 A1 A2 A3 A4]
同一像素的B通道：[B0 B1 ... B16]
输出有效通道：  [A0 A1 A2 A3 A4 B0 B1 ... B16]
```

CPU给出两路输入地址、通道数和输出地址，由硬件读DDR并组装结果。
目前支持两输入、沿通道拼接的INT16，不支持高/宽方向拼接或广播。

## 2. DDR填充和缓存

输入输出都按H-W-align16(C)存储，每元素2字节。
A、B的物理通道间距分别补齐，拼接时必须去掉各自填充区，再在最终输出尾部补零。
不能直接复制两张图的原始字节段，否则会把A的尾部填充插入A、B有效通道之间。
支持不按8/16对齐的有效通道数，包括5+17、17+5和31+2等情况。

使用一个128位源字缓存和一个128位输出字：

1. 根据输出通道判断该元素来自A还是B。
2. 若所需源字已缓存，直接取出对应INT16；否则发起16字节DDR读取。
3. 拼成8个INT16后写一个完整DDR字；输出填充位置显式置零。
4. 当前像素完成后，将A、B、输出基址分别增加各自的物理像素间距。

缓存可跨输出字复用，不为每个元素重新读取DDR。
输入A、B允许别名，输出禁止与任一输入重叠。状态切换前会完成当前DDR事务。
不扩大卷积MAC阵列；搬运通路不执行特征值乘加。实际逻辑、RAM/APM和时序仍需综合确认。

## 3. 量化尺度

Concat逐位保留输入INT16，包括-32768；没有RHU舍入或饱和。
若A、B尺度不同，拼接后仍是两组不同尺度的数据，下一层卷积按两组参数分别换算。
当前双尺度卷积要求分界为16通道对齐，参考C3模块的64+64等分界满足该条件。
不对齐的Concat本身支持；若其两路尺度不同且分界不满足卷积限制，需要额外适配，不能把group_split设0当作等价模型。
本次另用两路相同尺度的5+17通道网络验证不对齐拼接后接单尺度卷积。

## 4. 寄存器和任务表

复用既有AI寄存器，新增操作码3：

| 寄存器 | Concat含义 |
| --- | --- |
| AI_OPCODE | 3 |
| AI_INPUT | A地址 |
| AI_WEIGHT | B地址，此时不是权重 |
| AI_HW | 两路共同H、W |
| AI_CHANNELS | 低16位A通道数；高16位输出总通道数 |
| AI_GROUP | B通道数，此时不是量化分界，允许不按16对齐 |
| AI_OUTPUT | 输出地址 |
| AI_POST | 4，表示INT16输出，不调用量化计算 |
| AI_CONV、AI_BIAS、AI_QUANT | 必须为0 |

A、B通道数均须1..65535，和须不超过65535。
地址16字节对齐，范围按各张量自己的align16(C)×2字节间距检查。
不读取权重、偏置或量化表；错误和原生FAULT恢复方式沿用已有引擎。
mac_issues为0，cycles统计整个拼接任务。

AIM1版本2继续使用64字节任务，opcode=3，word2为B地址，word12为B通道数。
CPU在执行前检查全部描述符；打包工具检查两路INT16且H/W相等，自动安排输出尺寸和地址。
无需新增CPU跨域邮箱字段，仍复用已有opcode、channels及group寄存器。

JSON示例：

```json
{"name":"joined","op":"concat","input":"branch_a","input_b":"branch_b"}
```

下一层卷积以`input="joined"`读取结果，不需要CPU复制或重排。

## 5. 已验证什么

```bash
make test-ai-concat
python3 pc_ai/verify_w8a16_tasks.py --suite concat --prepare-only
# 更多CPU时钟组合，由用户执行等待：
python3 pc_ai/verify_w8a16_tasks.py --suite concat --profiles all
```

输出集中在`pc_ai/outputs/concat_tasks/`，C生成器为`pc_ai/export_concat_tasks.c`。
期望值直接来自参考`concat2`、`add_point`和`conv_layer`，Python只打包及启动测试。

- 16种独立DDR配置，包括1、5、8、9、15、16、17、31、32、33、64、288、384等通道组合。
- 输入填充故意非零、输出预填毒值；逐原生写拍和最终DDR结果检查，确保跳过输入填充、最终尾部写零。
- 检查实际DDR读命令数等于所需源字数，包含同一源字跨输出字复用和两输入同址的情况。
- 高宽跨多个像素、跨2KiB、512MiB顶部地址、21种非法配置、执行中复位、原生超时锁定及共同复位恢复。
- DDR正常、随机停顿、零读写延迟均通过；每组检查878个128位结果字，含2次重放。
- 同一CPU固件一次处理22次模型请求、19次AI提交，比较8977个DDR字；18种错误及不复位重跑通过。
- CPU只写报告；检查全部中间输出、输入/只读资产、哨兵、报告及性能计数。
- 完整参考C3块：cv1→双3×3→残差ADD，加上cv2旁路，再Concat→cv3，共7条任务。使用真实参数、1×3小特征图，最终输出还与原`c3fpga_fwd`核对。
- 补充5+17非对齐拼接后接卷积，以及重复拼接网络；原生FAULT停止及8位硬件拒绝16位包通过。
- Concat阶段统一固件3856字节；加入MaxPool5后4104字节的同一固件也已重跑本套检查通过。初始化数据段0；`ai_run_model`自身栈帧240字节，完整调用栈另计。
- 默认CPU任务配置为25MHz/DDR用户时钟约131.25MHz，其他时钟组合以报告为准；受影响的ADD和W8A8任务检查也通过。
