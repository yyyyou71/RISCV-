# 不接 RK 的 HDMI 独立自检

根工程 `rv32I.pds`，顶层 `acore_dual_top`，默认 `STANDALONE_CAPTURE=1`。
CPU、DDR、视频监测和预处理的应用复位由本地全局 25 MHz 时钟与 key0_n 生成，
不再依赖 PCIe 参考时钟、PERST# 或 PCIe core_rst_n。
PCIe IP 本身的时钟和复位连接保留；独立模式禁用原图 PCIe 读出，不占读槽、不向 DDR 发视频 AR。
CPU 仍可通过 DDR 窗口读回张量，HDMI 原图仍连续写入 DDR，并保留预处理选中的同帧原图。

恢复完整 RK/PCIe 模式时，把顶层 `STANDALONE_CAPTURE` 改为 0 后重新构建。
该模式恢复原参考工程的 PCIe 应用复位关系和原图读出。

## 当前固件与操作

ROM/RAM 已重新生成为 `firmware/preprocess_bringup/` 中的诊断镜像，嵌入内容逐字核对通过。
重新打开根工程，从 Compile/综合开始，完成布局布线、生成新位流后烧录。
保持 `groute_seed=3`，连接输出 1920×1080 的 HDMI 源；此次不需要连接 RK。

成功：LED1 每 0.5 秒翻转，保留一帧原图和预处理张量供检查。
失败：LED1 保持固定输出，LED0 循环发送下列闪码；每次短脉冲约 0.1 秒，组间停顿约 1 秒。
数每组的短脉冲次数，实际亮灭方向取决于板上 LED 极性。

| LED0 每组次数 | 错误阶段 |
| --- | --- |
| 1 | DDR 初始化等待超过 3 秒 |
| 2 | 2 秒内未检测到 1920×1080 输入尺寸 |
| 3 | 抓帧启动被拒绝（忙、持有旧结果或硬件故障） |
| 4 | 抓帧/预处理硬件返回错误 |
| 5 | CPU 等待抓帧结果超过 250 ms |
| 6 | 返回的张量长度或原图槽号不正确 |
| 7 | 张量首像素 DDR 读回或格式检查失败 |
| 8 | 张量末像素 DDR 读回或格式检查失败 |

在尚未进入错误闪码时，LED0 仍表示 DDR ready；进入错误后，GPIO[0] 通过异或方式发送脉冲，
因此即使共享硬件故障强制 LED1 固定，LED0 的诊断脉冲仍可观察。
`preprocess_diagnostic_stage/status/error/shape` 四个全局变量保留更详细的 RAM 快照。

当前未运行此版 PDS 综合、布局布线或生成位流，旧 P2 资源/时序报告不能作为独立模式的验收。
