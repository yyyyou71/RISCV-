# 自研 RISC-V + 轻量 YOLO 加速器设计方案

日期：2026-10-24。状态：架构规划、结构预算和 DDR 模型定向验证完成；加速器 RTL 尚未实现。

更新：用户已明确要求可更换模型的通用外设，并补充约十天期限、CPU/UART 已上板、另一工程真实 DDR 顺序读写已验证、SPI 由他人负责。最新取舍以 [十天方案](ai_accelerator_10day_tradeoffs.md) 为准；下文 YOLOv5n 为先前候选，不是最终锁定模型。

## 1. 本轮确定的方向

- 平台为 RK3568_MES2L100H 的 FPGA 部分，不使用 RK3568 执行控制或推理。
- 应用为目标检测并画框，具体识别对象、数据集和帧率尚未确定。
- 采用 RISC-V 调度、单个卷积引擎逐层复用、DDR 存放权重和特征图、片上缓存复用数据的结构。
- 第一候选为固定在 v7.0 的 YOLOv5n，batch=1，以 160×160 建立软件与硬件基线。
- 目标单类模型需要选定对象后微调。对象未定时，可用原版 COCO 80 类权重验证链路；仅筛选一个类别的结果不会把检测头变成单类头。
- 第一版数值格式为 W8A16：有符号 INT8 权重、有符号 INT16 激活、INT48 部分和；INT8 激活作为后续单独验证的优化。
- 单元调试从 4×4 MAC 开始；系统预算按 8 路输入 × 8 路输出、64 个乘法运算单元进行。实际 APM/LUT/DRM 占用和频率必须经 PDS 综合确认。

160×160 是起步输入尺寸，不是小目标检测精度承诺。场景确定后，要以软件检测效果决定是否提高到 192/256/320，并重新核算吞吐和缓存。

## 2. 两个参考工程的取舍

| 项目 | TridentVision | CNN_FPGA | 本工程采用的方式 |
| --- | --- | --- | --- |
| 计算组织 | 单引擎逐任务复用 | 各层分别实例化、层间流式连接 | 单引擎逐层复用 |
| CPU 作用 | MicroBlaze 解析任务、配置计算和后处理 | CNN 主链不依赖 CPU 调度 | 自研 RISC-V 执行调度和首版后处理 |
| 权重来源 | 外部存储、运行时装入缓存 | 各层权重 mem、按固定节拍读取 | DDR 权重镜像、分块装入片上缓存 |
| 中间特征图 | DDR + 局部缓存 | 行缓存、层间 FIFO/片上 RAM | DDR 保存层间结果，片上分块/行缓存服务当前层 |
| 更换模型 | 重新导出权重和任务 | 重新生成每层配置、权重和顶层连接，重新综合 | 算子集合内主要修改模型资产与任务表 |
| 主要借鉴 | 静态任务表、分块、量化参考、完成状态保存 | 滑窗、乘加流水、数据对齐、视频画框和同帧管理 | 组合上述机制，独立实现接口和可缩放计算核心 |

不能将两份数据通路直接串接：TridentVision 的激活为有符号 int16；CNN_FPGA 的 PDS PE 把 D 零扩展后参与乘法，常见激活为无符号 8 位，导出的权重为 9 位，输出层使用自己的移位、舍入和饱和规则。
实读 `node_conv2d.mat` 首层权重范围为 [-205,175]，不能直接截为 INT8 后沿用原黄金结果。

CNN_FPGA 的 PDS 主线在 `rtl_pds/`，`top_yolo.sv` 显式实例化 layer0..10；`w_manager.sv` 使用 `$readmemb` 预装权重，按周期读出。它的 DDR 主要用于原始视频延迟对齐，不是推理权重/特征图的运行时搬运层。
它部署于 PG2L200H，不能直接用其资源利用率、帧率推断 PG2L100H 的结果。

按当前生成头文件统计，YOLO 部分有 317 个空间展开 PE、117,592 个权重槽位、720p 下约 584.29M MAC 槽位运算；统计包含输出通道补齐，不等于实际模型参数量或实测吞吐。
对应 MAT 数据仍有 1280×1280/80×80 等原始导出形状，需要区分软件数据集尺寸与当前 1280×720 硬件配置。

## 3. 模型选择与完整算子范围

选择 YOLOv5n v7.0 是为了先建立有公开训练/预训练路径的小模型基线，不依赖参考工程专用车牌权重或 YOLO26m 改造训练流程。
保留原网络结构，首轮不同时修改激活、主干和检测头形式。

原始结构必须支持：

1. 卷积 K=1、3、6，stride=1/2，显式 padding；6×6 是第一层，padding=2。
2. BN 离线折叠、偏置、每输出通道权重量化、输出重定标。
3. SiLU：使用与整数参考一致的查表/分段近似，检测头末层旁路激活。
4. 残差 ADD：两路输入先按各自尺度对齐，不能直接对整数码相加。
5. 5×5、stride=1、padding=2 最大池化，用于 SPPF。
6. 最近邻 ×2 上采样。
7. 通道拼接；SPPF 有四路拼接，不能假定参考引擎的两输入接口已覆盖全部情况。
8. 三个检测头的 sigmoid、框解码、置信度筛选和 NMS。

第一版拼接可由 COPY/REQUANT 任务将输入写到同一目标区域，并统一量化尺度；全网验证通过后再实现多输入视图以减少复制。
替换 ReLU 或 3×3 首层可以作为将来重新训练后的分支方案，不能直接使用原权重冒充等价网络。

官方定义：
- https://github.com/ultralytics/yolov5/blob/v7.0/models/yolov5n.yaml
- https://github.com/ultralytics/yolov5/blob/v7.0/models/common.py

## 4. 可复算的结构预算

脚本：`scripts/ai_model_budget.py`。它展开固定版本的 60 个卷积，只统计卷积权重、卷积 MAC 及通道填充；不需要 PyTorch。

| 配置 | 卷积 MAC | INT8 权重字节 | 原始候选框 | 8×8、50MHz 假设下填充后的计算下界 |
| --- | ---: | ---: | ---: | ---: |
| 160×160，单类 | 129,011,200 | 1,755,712 | 1,575 | 46.16 ms |
| 320×320，单类 | 516,044,800 | 1,755,712 | 6,300 | 184.64 ms |
| 160×160，80 类 | 139,628,800 | 1,861,888 | 1,575 | 49.408 ms |

这些是结构推导和理想计算下界，不是仿真耗时、真实推理延迟或 FPS 承诺；尚未用 PyTorch profiler 交叉验证。
没有计入 DDR 传输、缓存空泡、激活、ADD、池化、上采样、拼接和 CPU 后处理。
例如单类 160 输入的有效计算下界是 40.316 ms；按 8 路通道补齐后为 46.16 ms，实际系统还会增加开销。

首层逻辑输出 80×80×16，INT16 占 204,800 字节；输入 RGB 若按 8 通道组补齐，占 160×160×8×2=409,600 字节。
这说明 64 KiB CPU RAM 不适合容纳完整特征图。权重、图像和中间特征图放 DDR，CPU RAM 留给程序数据、任务与后处理。
不能用“最大单张特征图大小”代替整图存储需求：还要保留分支结果、拼接区域、输入、输出和部分和。

复算：
```bash
python3 scripts/ai_model_budget.py --size 160 --classes 1 --lanes 8 --mhz 50
python3 scripts/ai_model_budget.py --size 320 --classes 1 --lanes 8 --mhz 50
```

## 5. 系统连接和职责

```text
自研 RISC-V + 原有 ROM/RAM
    │ 现有 dev_* 接口，固定同步读
    ▼
peripheral_bus
    ├─ UART
    └─ ai_mmio：配置快照、START、BUSY/DONE/ERROR、数据调试窗口、结果窗口
             │ 命令与完成事件；有时钟差异时经过 CDC
             ▼
        ai_engine
         ├─ 卷积/ADD/池化/上采样/COPY 控制
         ├─ ai_mac_array + ai_requant
         ├─ 输入缓存、权重缓存、部分和、输出缓存
         └─ 统一的字节地址存储请求
                    ▼
             ai_ddr_dma（DDR core_clk 域）
                    ▼
             现在：vsrc/ddr3.sv
             上板：同配置的紫光 DDR3 IP
```

CPU 负责逐任务调度、读取少量状态、首版检测后处理。它不逐个给 MAC 喂像素，也不拷贝每层大特征图。
暂不要求 CPU 对 DDR 建立普通 load/store 地址映射；用有限大小的结果/调试窗口，避免先改造 Acore 的可变延迟访存流水线。
后处理结果经 UART 输出 bbox，再加入 FPGA 画框模块；PC 可在调试阶段显示板上输出的坐标，但最终检测计算和显示叠加在 FPGA 系统完成。

## 6. DDR 行为模型的可用范围与专用适配

读取了 `vsrc/ddr3.sv`。它是 native 用户事务模型，包含初始化、命令队列、读写延迟、停顿、稀疏存储和 APB 子集。
引脚层保持空闲，PHY/debug 控制明确不支持；它不能证明真实校准、板级信号完整性、功耗或真实 DDR 带宽。
文件头引用的 `docs/ddr3_usage_report.md` 当前不存在。本方案只依据实际代码与本轮测试描述其行为，没有验证“完全等价于原厂 IP”。

默认 MEM_DQ_WIDTH=16：

| 项目 | 当前模型语义 | DMA 必须遵守的规则 |
| --- | --- | --- |
| 数据拍 | 8×16=128 bit，即 16 字节 | 缓存和数据打包按 16 字节自然对齐 |
| 原生地址 | x16 时一个原生地址单位为 2 字节，每数据拍步进 8 | 对齐字节地址先右移 1 位，再交给原生端口 |
| 地址对齐 | 原生低 3 位为 0 | 对应 DDR 线性字节地址按 16 字节对齐 |
| 突发长度 | 4 位 len，拍数=len+1，最多 16 拍 | 先限制到 16 拍，每段最多 256 字节 |
| 列地址 | 10 位；突发只在列内回绕，不进位到 bank/row | 软件线性连续传输必须在列边界拆成新命令 |
| 写数据 | 没有 WVALID；WREADY 有效即消耗当前数据 | 发 AW 前备齐整段数据，按 WREADY 推进，不能等到 WREADY 才准备当前拍 |
| 写完成 | 没有标准 AXI B 通道；提供 wusero_last/id | 核对末拍和 ID 后完成该段 |
| 读数据 | 没有 RREADY；每个 RVALID 必须接收 | 发 AR 前为整段预留缓冲空间，不能靠反压暂停 DDR 返回 |
| 初始化 | ddr_init_done 前命令不接受 | 保持复位/初始化握手，再提交命令 |

对于默认列宽，列边界对应 1024×2=2048 字节，而不是通用 AXI 的 4 KiB 分段规则。
设 `col = native_addr & 1023`，当前段拍数应满足：

```text
n = min(remaining_beats, 16, (1024 - col) / 8)
```

每段结束后按线性字节偏移增加 `16*n`，重新计算下一条原生地址。首尾不足整拍时使用写掩码、读后提取；第一轮模型资产先全按整拍对齐。
例如原生地址 0x3f8 发两拍会访问 0x3f8 和 0x000，而不会自动访问 0x400。需要拆成两个命令才能实现跨边界线性访问。

为简化第一版，DMA 每个方向先限制一个在途突发；不使用复杂乱序。复位、超时和异常必须让 CPU 看见错误，不能假装推理完成。

### 模型存储容量

默认 `DDR3_MODEL_SLOTS=65536`，x16 每槽 16 字节，只能保存约 1 MiB 已占用数据；高地址采用标签存储，不代表可以无限写入。
本轮小测试只用了 128 个槽。完整模型仿真建议从 `-DDDR3_MODEL_SLOTS=1048576` 开始，即 16 MiB 已写数据容量，再按导出报告的真实占用核对。
这是仿真模型容量，不是 FPGA 板实际 DDR 容量。稀疏表容量要包含仍被模型保留的历史写入地址，回收模型 tensor 不会自动释放表项。

初步 DDR **字节偏移**规划如下，不是 CPU 可直接解引用的地址：

| 偏移范围 | 预留 | 用途 |
| --- | ---: | --- |
| 0x00000000..0x001fffff | 2 MiB | 权重与量化常量 |
| 0x00200000..0x002fffff | 1 MiB | 输入图像、打包后的模型输入 |
| 0x00300000..0x00afffff | 8 MiB | 中间特征图、分支和拼接区域 |
| 0x00b00000..0x00bfffff | 1 MiB | 检测头输出、结果 |
| 0x00c00000..0x00ffffff | 4 MiB | 调试和暂存 |

这是分区预留，不是已验证的分配结果。编译器必须输出实际占用与生命周期图；大分辨率摄像头帧缓冲另行规划。

### 时钟

模型默认用自身产生的 core_clk，周期约 7.619 ns；这不是 CPU 或新加速器已经能达到的频率。
DDR 适配器在 core_clk 域工作。系统阶段 CPU/计算域和 DDR 域之间用命令、写数据、读数据异步 FIFO，完成事件用可靠握手。
第一轮 DMA 单元测试直接用 core_clk 简化验证，再单独测异步时钟组合；不能直接跨域传一拍 START 或多位地址总线。

## 7. 计算核心、缓存和数值规范

生产起点为 8×8 MAC：每拍处理 8 个输入通道的点积，生成 8 个输出通道的部分和；同一激活向量广播到 8 个输出通道。
三级乘法/求和/累加流水，first、last、valid、通道组标识一起延迟。输入通道和输出通道不足一组时补零。
原参考 `mac_array.v` 的 ICH 求和写死为 16，不能直接设成 8；需要真正按参数生成归约树。

INT16 的 8 通道激活正好装入一个 128 位 DDR 拍；8×8 个 INT8 权重为 512 位，通过缓存供给，不从外存逐拍直接取 512 位。
每输出通道 INT48 累加。定标乘法需按实际乘积位宽和模型边界设计，不能默认所有 INT48×INT32 乘积都能无损装入 INT64。

初始缓存预算用作模块划分：
- 输入 tile 约 16 KiB，按实际核大小保留 halo；支持 6×6，不能只写死 3 行。
- 权重缓存约 16 KiB，分输出/输入通道块装载。
- 输出 tile 约 8 KiB，另有独立部分和存储。
- DDR 突发 staging 每段至少 256 字节，ping-pong 时预留两段。

上述不是综合结果；具体 tile 尺寸和部分和容量由导出层表与 PDS 可用 DRM 决定。
先单缓冲保证正确，再加入双缓冲重叠。跨输入通道块时保持完整部分和，只在该输出的全部输入通道累加完后量化；避免因每块先舍入而改变定义。

量化约定先冻结成 Python 整数参考：
- 权重每输出通道对称 INT8，激活每 tensor 对称 INT16；零点为 0。
- RGB 输入归一化、RGB/BGR 顺序、letterbox/crop、填充值与训练/校准完全一致。
- BN 在 PC 上折叠，导出偏置、乘数和移位；bias 使用明确的定点域。
- 舍入、负数右移、饱和范围、SiLU LUT、padding 值全部显式定义。
- 整数参考用足够宽的宿主整数；导出时报告硬件中间位宽上界与饱和次数。

全网验证前不混用另一个工程的 9 位权重、无符号激活或不同舍入规则。

## 8. CPU 接口和后处理

建议 `ai_mmio` 基址 0x00030200，保留现有 UART 0x00030100/0104。
配置窗口只使用对齐的 32 位访问，与当前 peripheral_bus 同步读时序一致。

建议寄存器组：CTRL、STATUS、ERROR_CODE、OPCODE、SRC0/SRC1/DST/WEIGHT、H/W/CIN/COUT、K/S/P、量化常量装载口、周期计数和结果窗口。
门铃只在空闲时接受；接受时快照配置、清除旧完成状态。运行中配置写入不得改变在途任务。
DONE/ERROR 保存到软件明确清除或下一任务被接受；DONE 必须晚于最后一段写回完成。
首版使用轮询，不要求先完成中断、Cache 或 CPU 直接 DDR 访存。

首版 CPU 完成 sigmoid LUT、YOLOv5 框解码、候选筛选、Top-K 和整数 NMS。
单类 160 输入只有 1575 个原始候选；建议置信度筛选后限制 Top-K≤100，最大输出框≤20，再实测 CPU 耗时。
使用有界查表和结果缓冲，不移植参考固件 3×64K 个 int32 的 sigmoid 全表（768 KiB）。
80 类调试模型的检测头更大，应分块读取、逐框归约，不能假定它与单类模型具有相同 RAM 需求。

CPU 首版可以通过 MMIO 结果窗口取得检测头数据，避免假设它能直接读取 DDR。优先实测后处理是否成为瓶颈，再决定是否硬化阈值筛选、Top-K 或 NMS。

## 9. 软件模型、导出与验证资产

模型路径应形成可重复链路：

```text
固定版本 YOLOv5n → 选定对象/数据 → 浮点基线与微调
 → BN 折叠 → W8A16 校准（必要时 QAT）
 → 独立整数参考 → 每层黄金输出
 → 权重/常量打包 + 存储分配 + 任务表
 → 单层 RTL 对拍 → 全网 RTL 对拍 → 上板静态图 → 视频
```

当前 Python 环境有 numpy/scipy/yaml，没有 torch/onnx/ultralytics。本轮未安装训练环境、下载权重或宣称模型已量化完成。
PC 可以用于离线训练、导出和验证；部署时计算留在 FPGA。

需要交付的工具：模型清单、整数参考、任务编译器、权重打包器、层间结果比较器、裸机驱动与后处理。
导出清单至少含：源模型版本/校验、输入预处理、类别、每层形状和量化参数、权重偏移、特征图偏移与生命周期、MAC/填充预算、模型资产校验、黄金图像和 bbox。

“整数参考和 RTL 一致”与“模型能正确检测目标”分别验收：前者检查实现，后者用浮点/定点检测精度、召回与场景测试判定。
具体精度门限在对象与数据集确定后制定，不能从两个参考工程的宣传帧率推出。

## 10. 视频与同帧画框

借鉴 CNN_FPGA 的 overlay 和同帧意识，但复用引擎的延迟可能随 DDR 仲裁变化，不能只用固定拍数延迟视频来对齐。
每帧携带 frame_id，维护采集、推理、显示缓冲的所有权。结果与对应原始帧关联后才画框。
忙时允许丢弃新帧，但不能覆盖推理仍在读取的帧。
视频输入、输出引脚是否直接连接 FPGA，需要根据本板原理图核对，不能借用 RK3568 的视频链路。

| 阶段 | 交付 | 必须满足的验收 |
| --- | --- | --- |
| S0：基线 | 固定模型、预处理、数据与浮点 bbox | PC 上先确认所选分辨率能检测场景目标；对象未定时用预训练模型作链路样例 |
| S1：DDR 适配 | ai_ddr_dma + 行为模型测试 | AW/AR 停顿、WREADY 停顿、RVALID 空泡、跨列拆段、部分字节、复位/超时、buffer 边界正确 |
| S2：计算单元 | MAC、定标、缓存、地址生成 | 符号、边界、空泡、首次/末次、不同通道数和核尺寸全部对拍 |
| S3：单层闭环 | DDR 输入/权重 → 卷积 → DDR 输出 | K=1/3/6、stride=1/2、padding、通道补齐、多输入块逐项匹配 |
| S4：CPU 控制 | MMIO + 裸机程序，连续执行两层 | 配置不被在途写改变，完成状态不丢失，最终结果匹配参考 |
| S5：完整网络 | 其余算子、编译器、全网静态图 | 每层整数输出一致，CPU 后处理框与参考一致，记录各段周期 |
| S6：视频 | 采集、预处理、frame_id、画框输出 | 同帧、无缓冲覆盖，输出检测率与显示刷新率分开报告 |
| S7：优化 | 双缓冲、融合、更多并行度/INT8 激活 | 每项优化后保持正确性，并给出 PDS 资源、时序、带宽与端到端收益 |

眼下最先落 RTL 的模块应是 `ai_ddr_dma`：先把已有 DDR 模型变成加速器可安全使用的存储接口，再完成一层从 DDR 读写的卷积；MAC 的算术单元可独立验证。
第一阶段无需先实现完整异常中断，也无需让整个 Acore 因一次卷积而停顿。
